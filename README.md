# 文明演进 · Civilis

一个纯前端、放置（idle / incremental）+ 文明演进类游戏。

玩家从一簇篝火旁的采集者起步，依次经历定居、城邦与帝国，通过资源积累、岗位分工、科技研究、贸易交换和军事扩张，把文明从蒙昧推向统一。项目以“真实文明史的技术演进”为主线，每个时代都必须带来新的动词、新的瓶颈和新的决策，而不是单纯放大数值。

> **当前版本状态**：E1-E4 已实装并可完整游玩；E4 已形成“钢铁与铸币 → 军团征伐 → 平定扩地 → 统一天下”的闭环。E5-E8 已完成设计规划，尚未接入可玩运行时。

## 游戏体验

### 四层循环

| 层级 | 玩家在做什么 |
|---|---|
| 微观 | 把人口分配到采集、耕作、冶炼、贸易、铸币或军团等岗位 |
| 中观 | 建造建筑、研究科技、开通商路、签订契约 |
| 宏观 | 判断何时推进时代，并处理新时代的瓶颈 |
| 元循环 | 继承文明积累，规划未来的文明重启与长期成长 |

### 时代总览

| 时代 | 主题 | 新动词 | 当前实装内容 |
|---|---|---|---|
| E1 远古时代 | 火、石器与生存 | 采集、生火 | 火种维护、工具世代、人口承载力、三条基础科技分支 |
| E2 定居时代 | 农业革命 | 种植、驯养 | 四季循环、田地、牲畜、织物、粮仓与越冬压力 |
| E3 城邦时代 | 青铜城市与交换 | 记录、交换 | 泥板刻录、知识、铜锡供应链、五邻邦贸易与契约 |
| E4 帝国时代 | 战国至秦统一 | 征伐、扩张 | 钢铁、铸币、军团、军饷、版图平定、统一天下 |

#### E1 · 远古时代

- 初始人口只有 2 人，资源极少，必须先解决食物与火种问题。
- 火种会持续衰减，需要用木材维护；火种档位影响产出与人口承压。
- 玩家逐步解锁采集者、伐木者、打石者和猎人。
- 猎人受猎场承载力约束，人数越多，边际收益越低。
- 科技分为“火之技艺”“石器与工具”“群体与定居”等路线，最终汇聚到门槛科技“植物栽培”。
- E1 门槛条件：`食物 ≥ 300`、`住所 ≥ 3`、`人口 ≥ 15`，并研究“植物栽培”。

#### E2 · 定居时代

- 核心科技是“农业”，开启四季循环。
- 一年由春、夏、秋、冬四季组成，每季 60 秒，一年 240 秒。
- 农业在秋季获得主要收成，冬季大幅衰减；人口与存粮共同决定越冬结果。
- 牲畜是活体储备，可在缺粮时宰杀，也会持续消耗饲料。
- 织物用于提高舒适度，粮仓、田地、畜栏和陶窑构成本代基础设施。
- E2 门槛条件：`食物 ≥ 1500`、`人口 ≥ 75`、完整度过 `8` 个冬季、`粮仓 ≥ 3`、`田地 ≥ 8`，并研究门槛科技“文字”。

#### E3 · 城邦时代

- 核心科技是“楔形文字”，它将经验推进为可被记录的“知识”。
- “经验”和“知识”不是两个底层字段，而是同一个 `experience` 资源在不同时代的显示名称。
- 书吏产出知识；记录容量由“基础槽位 + 学宫 + 泥板科技”组成。
- 未刻录科技只发挥部分效果，刻录后成为稳定文明积累；刻录不可撤销。
- 本地不能稳定获得锡，青铜生产必须依赖贸易。
- 贸易包含固定邻邦、陆路与水路、距离损耗、价格波动、需求冲击、声望、契约、违约惩罚和路线中断。
- E3 门槛条件：`人口 ≥ 1800`、`青铜 ≥ 2000`、`已刻录科技 ≥ 12`、`学宫 ≥ 3`、`商栈 ≥ 2`，并研究门槛科技“钢铁”。

#### E4 · 帝国时代

- 主题是**军事扩张带动生产**，生产与后勤服务于战争。
- 时代风格取自中国古代封建、战国兼并至秦统一的军事与制度演进。
- 旧版秩序、政体、官吏、法典、行政覆盖率和规模不经济机制已经删除，不作为后续 E4 的实现来源。
- 核心科技是“钢铁”，主要路线为钢铁与铸币、后勤与编户、军略与统一。
- 新增资源为铁与铸币；新增岗位为铁矿工、铸币工和军团兵；新增建筑为驰道、铸币厂、军团营垒和武库。
- 玩家通过军团征伐不断扩张版图，版图提高人口承载力与物产，同时让下一次征伐更昂贵。
- E4 完成条件：研究“统一天下”、`版图 ≥ 20`、`铸币 ≥ 150000`、`军团营垒 ≥ 4`。

## E4 核心闭环

```text
铁矿工 -> 铁 -> 铸币厂 + 铸币工 -> 铸币 -> 军团军饷
   |                 |                         |
   |                 +-------- 征伐成本 -------+
   +---- 营垒 / 武库 / 驰道 / 兵器成本 -------+
                                                 |
                                                 v
                                       军团 + 铁 + 铸币
                                                 |
                                                 v
                                             发动征伐
                                                 |
                                        平定期结束，版图 +1
                                                 |
                          人口承载力、物产和知识产出提高
                                                 |
                              下一次征伐与军费需求同步提高
                                                 |
                                                 v
                                        军工扩建与统一科技
                                                 |
                                                 v
                                             统一天下
```

E4 的主要数值边界：

- 版图最大为 `24`。
- 版图物产倍率为 `(1 + 0.08 × (版图 - 1)) × 科技倍率`。
- 版图承载力为 `60 × 版图^0.85 × 科技倍率`。
- 征伐同时消耗军团、铸币和铁；平定期结束后版图增加。
- 军团持续消耗食物与铸币，铸币工生产铸币时消耗铁。

## 当前资源

资源栏采用渐进显隐：时代和科技没有解锁的资源不会提前显示一排 0，也不会在进入新时代后无条件塞满界面。

| 资源 | 解锁时代 | 主要用途 |
|---|---|---|
| 食物 | E1 | 人口消耗、越冬、牲畜饲料、贸易与军粮 |
| 木材 | E1 | 火种、建筑、工具与后期军需 |
| 石头 | E1 | 石器、建筑与设施 |
| 经验 / 知识 | E1 | E1/E2 显示“经验”，E3 起显示“知识”，用于研究科技 |
| 人口 | E1 | 劳动力池、知识积累与人口门槛 |
| 牲畜 | E2 | 活体粮食储备，也有容量与饲料约束 |
| 织物 | E2 | 提高舒适度，也可作为贸易出口品 |
| 铜 | E3 | 冶炼青铜、建筑和冶金链 |
| 锡 | E3 | 青铜关键原料，主要依赖贸易 |
| 青铜 | E3 | 工具世代、建筑、贸易与时代跃迁 |
| 青金石 | E3 | 远方贸易珍宝，需要对应商路科技 |
| 铁 | E4 | 铸币、军团营垒、武库、驰道与征伐 |
| 铸币 | E4 | 军团军饷、领土扩张与后续时代资本 |

人口不是普通材料，资源栏会把它按“当前人数 / 上限”和增长速率单独显示。

## 当前岗位与建筑

### 岗位

| 时代 | 岗位 |
|---|---|
| E1 | 采集者、伐木者、打石者、猎人 |
| E2 | 农夫、牧人、织工 |
| E3 | 矿工、冶炼工、书吏、商人 |
| E4 | 铁矿工、铸币工、军团兵 |

岗位不是简单的线性叠加：

- 采集者可随农业与工位条件专职化为农夫。
- 打石者可随工具与采矿科技转向矿工。
- 猎人受猎场总承载力限制，适合早期，不适合无限堆叠。
- 商人提供贸易运力，书吏同时支撑知识生产、刻录和商路维护。
- 军团兵提供征伐与驻防能力，但持续消耗食物和铸币。

### 建筑

| 时代 | 建筑 |
|---|---|
| E1 | 住所、火塘、作坊 |
| E2 | 村落民居、田地、粮仓、畜栏、陶窑 |
| E3 | 民居、熔炉、学宫、商栈、标准器、仓库 |
| E4 | 驰道、铸币厂、军团营垒、武库 |

建筑采用逐座成本蠕变，不同类别使用不同倍率，避免“无限建造但成本恒定”。部分住所支持 1:1 升级，火塘等绑定旧时代独有机制的建筑会在机制退役后随时代退场。

## 科技系统

科技树总计 94 项，按照“核心科技 → 多条发展分支 → 时代之门”组织。

| 时代 | 科技数量 | 主要分支 |
|---|---:|---|
| E1 | 20 | 文明之光、火之技艺、石器与工具、群体与定居、时代之门 |
| E2 | 30 | 文明之光、耕作与节律、驯养与活体储备、定居与储藏基建、时代之门 |
| E3 | 23 | 文明之光、书写与记录、青铜与制造、贸易与度量、时代之门 |
| E4 | 21 | 文明之光、耕战与后勤、军略与扩张、时代之门 |

主要规则：

- 科技研究消耗“经验 / 知识”这一套统一货币。
- 旧时代科技在研究进入新时代后仍然可见、可研究、可刻录。
- 时代门控只用于阻止未来内容提前出现，不会反向剥夺已经获得的旧内容。
- E3 的记录系统会把知识沉淀为泥板档案；未刻录科技与已刻录科技的效果不同。
- E4 的军略路线最终汇聚到“统一天下”，不再使用旧版法典或政体科技作为时代终点。

## 贸易系统

E3 的贸易不是静态加成，而是一套持续运行的路线系统：

- 5 个固定邻邦：迪尔蒙、南方城邦、埃兰、玛甘、美鲁哈。
- 9 类可贸易物资：食物、木材、石头、牲畜、织物、铜、锡、青铜、青金石。
- 每 30 秒结算一个商队周期。
- 路线区分陆路与水路，距离、运输方式和科技会改变价格与运力。
- 价格受基准价、距离、需求冲击、随机波动、声望、契约和换算损耗影响。
- 每项科技可被刻录，记录容量来自基础槽位、学宫与相关科技。
- 路线可能发生中断、拒交或资源不足，并会把状态写回路线卡和消息日志。
- 玩家可以签订契约锁定价格和提升运力，但毁约会带来声望与价格惩罚。
- 面板展示最近价格历史与趋势，帮助玩家判断何时买入。

## 模拟、存档与离线收益

- 时钟运行在 Web Worker 中，减少浏览器后台节流造成的漂移。
- 在线、离线与开发模拟共用同一套 `game/simulation` 和 `engine.tick()`。
- 快速循环、中速循环与慢速循环分工处理资源、状态和游戏日事件。
- 离线收益使用在线等效结算，带效率系数与最长 8 小时上限。
- 存档使用 `localStorage`，包含自动存档、导入、导出和版本迁移。
- 随机贸易结果使用可保存的种子随机数，便于复现和回归测试。
- P1 文明重启状态与遗产收益公式已经进入 E4 状态模型和界面；当前 demo 尚未提供完整的可重复文明重启操作，“重置存档”仍然是清空进度的开发功能。

## UI 设计

当前入口为 `demo/src/ui/AppShellV2.tsx`。

- 竖屏采用抽屉式布局，状态、资源和消息按需展开。
- 横屏采用左栏数据、中间操作、右侧或底部反馈的结构。
- 横屏常驻火种 / 季节摘要，竖屏使用状态抽屉保存空间。
- 资源栏单行滚动，不因资源增多而换行挤压主内容。
- 科技区同时提供可研究列表和依赖图谱。
- 建筑、岗位、贸易路线使用紧凑方块与详情卡，失败时会说明缺少什么。
- 数字使用等宽与 `tabular-nums`，避免 tick 更新时布局抖动。
- 消息日志支持分类筛选，重要事件可以被单独查看。
- 支持布局偏好保存、左栏拖拽调宽和键盘数字键切换主 Tab。

## 架构边界

项目采用数据、规则、状态、基础设施和 UI 分层，规则层不直接依赖 React 或 DOM。

| 层 | 目录 | 职责 |
|---|---|---|
| 基础设施 | `demo/src/core` | 时钟、随机数、格式化和通用工具 |
| 数据 | `demo/src/data` | 资源、岗位、建筑、科技、时代与常量 |
| 规则 | `demo/src/game` | 计算、生产、研究、贸易、记录、跃迁和模拟 |
| 状态 | `demo/src/state` | Zustand 状态、用户操作和存档落库 |
| UI | `demo/src/ui` | 展示、交互、响应式布局和反馈 |
| 验证 | `demo/src/dev` | 回归、模拟和可达性诊断 |

标准数据流：

```text
data -> game 纯函数 -> state/store -> UI
                     \-> dev/regression
```

核心开发原则：

1. **可达性优先**：科技、资源和时代条件都不能出现循环依赖或启动死锁。
2. **时代引入新动词**：新时代不能只是“数值更高”，必须产生新玩法。
3. **继承优先于重置**：跃迁默认只新增内容，不清空玩家积累。
4. **数据驱动**：规则放在 `data` 与 `game`，不在 UI 重复实现。
5. **玩家可解释**：失败、缺料、路线中断和条件不足都必须有明确反馈。
6. **小步验证**：每组改动独立回归、构建、提交和推送。

## 后续路线

| 时代 | 计划主题 | 新动词 | 状态 |
|---|---|---|---|
| E5 远洋 | 大航海、火药与印刷 | 复制、探索 | 规格已细化 |
| E6 工业 | 蒸汽机、工厂、铁路与电报 | 工业化 | 规格已细化 |
| E7 电气 | 电力网、内燃机与化学合成 | 规模化、机动化 | 规格已细化 |
| E8 信息 | 计算机、半导体与网络 | 计算、联网 | 规格已细化 |

长期重置已经规划为三个层级：

- **P1 文明重启**：首次到达 E4 后进入状态模型，当前仍等待完整玩法闭环。
- **P2 平行文明**：通关后选择河谷、草原或海洋起源。
- **P3 星际播种**：作为现代之后的长线终局扩展。

## 已知边界

- E5-E8 只有设计与开发规划，尚未成为可运行内容；E4 完成后会进入“新时代交接待开放”边界。
- P1 已有解锁标记、遗产点字段和收益公式，但重复文明重启的完整交互尚未开放。
- 当前没有服务端、云存档、账号系统或多人功能。
- 所有存档都在浏览器本地，清理站点数据会删除进度。
- 贸易、季节和离线结算都使用确定性模拟，回归脚本应作为改动的主要安全网。
