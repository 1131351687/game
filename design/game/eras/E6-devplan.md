# E6 机器时代 · 开发任务清单

> **来源**：[`E6-machine.md`](./E6-machine.md)（设计规格）＋ 本代铁律（时代进展提案）
> **状态**：📐 **实施级规格已完成**（2026-09-12）—— 拍板后即可按第八节的工作块开工
> **目标**：把 E6 实装为可玩的一代，**并且不破坏 E1/E2 的既有基线**
> **基线**：`demo/` 现有代码 —— 已实装 E1 + E2，`autoplay beeline` 1163s / `autoplay e2` 1920s 不可被影响（所有新机制时代门控）。SAVE_VERSION：E3=6、E4=7、E5=8、**E6=9**（每代 +1）
> **承接关系**：E6 的研究货币**沿用 E3 起的「知识」**（设计文档 §6 明确列「知识」为本代研究货币；E5 称「研究点」属于命名层差异，见第四节矛盾 1）。E6 核心科技「蒸汽机（工业应用）」即 E5 的门槛钥匙——同一台机器在 E6 从「抽水样机」升级为「工业动力源」，**花费不重复**（买的是能量链系统本身）。

> **本代的独特之处**：E6 是继 E3 之后又一次**最大跨代跳跃**，且机制复杂度最高。它一次性引入
> ① **能量链**（煤 → 蒸汽 → 机械能 → 电，每加一环损耗一次 η 乘法）② **蒸汽压力仪表盘**（本代视觉主角，地位＝E1 火种）
> ③ **电网 ρ 供需平衡**（朴素版，E7 升级为主干）④ **五段瓶颈转移**（煤荒 → 钢荒 → 电气化陷阱 → 电荒 → 输电荒）
> ⑤ **城市化**（逻辑斯蒂首次出现「环境代价」：拥挤系数 + 卫生因子两个负向 r 因子）⑥ **污染 → 卫生因子**
> ⑦ 工厂规模效应（单位人力产出 ×12）。前代经验（E3 的 η 体系、E5 的电网雏形）可部分复用，但 E6 必须按下面的顺序推进。

### T2 · 引擎层（建议新建 `game/energy.ts` + `game/urban.ts`，纯函数优先）

> ⚠️ **铁律：所有新机制必须时代门控**（`state.era >= 'E6'` 或「相关建筑/岗位是否 >0」判定），
> 否则会污染 E1/E2 的既有基线（1163s / 1920s）与 SSR 字节一致性。

- [ ] **T2.1 能量链（核心机制）** ← **本代最重，η 乘法见第三节 3.2**
  - `getCoalBurned(state)` = `min(coalStock, 司炉工×5)`（司炉工照看 5 煤/秒）
  - `getSteamTier(state)`：从科技推导世代 I/II/III/IV → η₂；缺档时返回当前最高已研究世代
  - `calcMechanicalRaw(state)` = 煤燃烧 × 100 kW × η₁ × η₂_eff（η₂_eff 含压力喘振惩罚 ×0.4，见 T2.4）
  - `calcSupplyRate(state)`：直驱 `mechRaw × η_trans(n) / (工厂×60)`；电气化 `G/D` → ρ（见 T2.2）
  - `tickEnergy(state, dt)`：推进煤耗、机械能产出、电网 G/D/ρ，返回 `{mechSupply, rho, gridG, gridD}`
  - **验收**：纽科门直驱 1 厂总效率 = 0.45×0.02×0.926 ≈ 0.83%；高压复式电气化 15 厂 = 0.45×0.22×0.85×0.94×0.88 ≈ 6.96%（与 §1.2 逐条对上）

- [ ] **T2.2 电网 ρ（朴素版，E7 升级为主干）**
  - `calcGrid(state)`：`G = mechRaw × η₃ × η₄`（发电侧）；`D = 工厂×150 + 住宅×2 + 锅炉房×15`（耗电侧，电气模式才计住宅/锅炉）；`ρ = min(1, G/D)`
  - 朴素版：**单区 ρ**（无分区），E7 再扩为多区算力供电
  - `applyGridThrottle(rho)`：ρ=1 满速；0.6≤ρ<1 全厂 ×ρ；ρ<0.6 追加拉闸（r×0.7 + 暗角）；ρ<0.2 电网崩溃（×0.3，蒸汽冗余接管——见 §10「质」作用）
  - **验收**：建足发电厂后 ρ 趋近 1；发电不足时工厂产出按 ρ 平滑下降（非暴死）

- [ ] **T2.3 工厂产出（机械师不再直接产出）**
  - `calcFactoryOutput(state)` = `6 × 规模系数(n) × 供给率 × 科技加成 × ρ（电气模式）`
  - `规模系数 = 1 + 0.20 × min(工厂数, 15)`
  - 机械师提供「人」但产出来自能量：机械能不足时多派机械师是纯浪费（UI 提示「先看压力表」）
  - **验收**：15 厂总产出 = 360 工业品/秒（与 §1.4 对上）；煤断供时工厂产出归 0

- [ ] **T2.4 蒸汽压力与喘振**
  - `tickSteam(state, dt)`：司炉工维持 → 压力上升；自然衰减 `1.5/s × (1 − 0.15×锅炉房数)`；上限 `100 + 20×锅炉房`
  - 档位判定：静止 0 / 微压 1–33 / 常压 34–66 / 高压 67–100；**压力低于当前世代所需档位 → η₂_eff = η₂ × 0.4（喘振）**
  - **验收**：压力表掉档时总效率骤降且 UI 脉冲；压力满档时产出 ×1.0

- [ ] **T2.5 城市化与污染（r 的两个负向因子）**
  - `getUrbanizationRate(state)`：U = `min(1, 工人住宅承载 / max(population,1))`（城市人口口径，见矛盾 8）；驱动拥挤系数表（≤40%→1.0 … >85%→0.45）
  - `tickPollution(state, dt)`：累积 `Σ工厂×0.008/s − 治理速率`；卫生因子 = `1 − Pol/250`
  - `getGrowthRateE6(state)`：`r = 0.02 × 拥挤系数 × 卫生因子`（× 食物生存因子；季节在 E6 关闭，seasonR=1）
  - **验收**：未治理后期 r≈0.0089、治理后 r≈0.0112（与 §4.4 对上）；污染→卫生因子拖住人口可被治理逆转

- [ ] **T2.6 研究货币与跃迁条件扩展**
  - `getResearchCurrency(state)`：E1/E2→经验；E3+→知识（E6 沿用知识，见矛盾 1）
  - `calcKnowledgeOutputE6(state)` = `人口 × 0.3 × (1 + 0.03N)`（N=已研究 E6 科技数，复利从 0 起步；印刷术 k×0.6 已并入 0.3 系数）
  - `checkAdvanceE6`：六项（研究「电力」+ 钢≥200,000 + 工厂≥15 + ρ≥0.90 + 人口≥3,600 + 城市化率≥70%）
  - **验收**：六项条件在 UI 逐条显示 ✅/⬜ 与进度；旧时代跃迁条件字面上未变

**T2 验收**：为以上六个子系统各写一段可跑的验证脚本（放进 `src/dev/`，跑完即删），
证明「新机制正确」且「旧机制未变」。

// 能量链运行时派生（不存档，每 tick 重算；仅 steamPressure/pollution 是积分态需存档）
interface EnergyRuntime {

### 3.2 能量链的 η 乘法（**本代最值钱的部分，单独成节**）

> 设计意图：玩家优化的是**转化效率**。每加一环，就多一次 η 乘法打折；但每一环也是突破物理瓶颈的唯一办法。
> 下面把 `E6-machine.md` §1.1/§1.2/§3.1/§3.3 的两套描述（§1.2 链式效率 vs §3.1 电网 G/D）**统一为单一计算路径**，
> 避免重复惩罚（详见矛盾 2）。

```ts
// ── η 常量表（来自 §11.2，全部可悬停查看来源）──
const ETA = {
  boiler: 0.45,          // η₁ 锅炉（焦炭冶炼 → 0.495）
  steamGen: {            // η₂ 蒸汽机世代（含压力档位惩罚）
    I:   0.020,          // 纽科门机
    I5:  0.045,          // 斯米顿改良
    III: 0.090,          // 分离冷凝器
    IV:  0.220,          // 高压 + 复式膨胀
  },
  generator: 0.85,       // η₃ 发电机（法拉第电磁感应）
  transmit: { dc: 0.78, ac: 0.88, hvac: 0.94 }, // η₄ 输电（直流/交流/高压交流）
  motor: 0.88,           // η₅ 电动机
};
const COAL_KW_PER_UNIT = 100;   // 1 煤 = 100 kW·秒
const FACTORY_MECH_KW = 60;     // 每座工厂机械能需求（轴端）
const FACTORY_ELEC_KW = 150;    // 每座工厂耗电（电网端，含电动机/传输开销）
const STEAM_ENGINE_KW = 110;    // 每台蒸汽机机械能产能
const POWER_PLANT_KW  = 190;    // 每座发电厂电力产能
```

```ts
// ── 核心：煤 → 末端可用能 的总效率 ──
// 直驱路径（无发电厂）：煤 → 热(η₁) → 机械能(η₂) → 传动(η_trans)
//   总效率 = η₁ × η₂ × η_trans(n)，  η_trans = 1 / (1 + 0.08 × 工厂数)
// 电气化路径（有发电厂）：煤 → 热(η₁) → 机械能(η₂) → 电(η₃) → 输电(η₄) → 机械能(η₅)
//   总效率 = η₁ × η₂ × η₃ × η₄ × η₅

function getBoilerEta(state): number {
  return state.techs['coke_smelting'] ? 0.495 : ETA.boiler; // 焦炭冶炼提升 η₁
}
function getSteamEta2(state): number {
  // 取当前最高已研究世代；压力不足档位时在调用方乘 0.4（喘振）
  if (state.techs['high_pressure'])      return ETA.steamGen.IV;
  if (state.techs['separate_condenser']) return ETA.steamGen.III;
  if (state.techs['smeaton'])            return ETA.steamGen.I5;
  if (state.techs['newcomen'])           return ETA.steamGen.I;
  return 0; // 未研究蒸汽机（工业应用）则无能量链
}
function getTransmitEta4(state): number {
  if (state.techs['hvac_transmission']) return ETA.transmit.hvac;
  if (state.techs['ac_transmission'])   return ETA.transmit.ac;
  if (state.techs['dc_transmission'])   return ETA.transmit.dc;
  return 1; // 未研究输电：电气化不可行（ρ 恒 <1）
}

// ── 机械能毛产出（蒸汽侧，两路径共用）──
function calcMechanicalRaw(state): number {
  const coalBurned = Math.min(state.coal, (state.jobs.stoker ?? 0) * 5); // 司炉工照看 5 煤/秒
  const eta2eff = getSteamEta2(state) * pressureTierPenalty(state);       // 喘振 ×0.4
  return coalBurned * COAL_KW_PER_UNIT * getBoilerEta(state) * eta2eff;
}

// ── 供给率（工厂产能的单一节流源）──
function calcSupply(state): EnergyRuntime {
  const mechRaw = calcMechanicalRaw(state);
  const n = state.buildings.factory ?? 0;
  const plants = state.buildings.power_plant ?? 0;
  const housing = state.buildings.worker_housing ?? 0;
  const boilers = state.buildings.boiler ?? 0;

  if (plants > 0) {
    // 电气化：发电机把机械能转电，电网供需决定 ρ
    const G = mechRaw * ETA.generator * getTransmitEta4(state); // 发电侧（kW）
    const D = n * FACTORY_ELEC_KW + housing * 2 + boilers * 15;  // 耗电侧（住宅/锅炉仅电气模式计）
    const rho = D > 0 ? Math.min(1, G / D) : 1;
    const mechSupply = G * ETA.motor;            // 送达工厂轴的机械能（含 η₅）
    const supplyRate = Math.min(1, mechSupply / (n * FACTORY_MECH_KW || 1));
    const totalEta = getBoilerEta(state) * getSteamEta2(state) * ETA.generator * getTransmitEta4(state) * ETA.motor;
    return { coalBurned: Math.min(state.coal, (state.jobs.stoker ?? 0) * 5), mechRaw, mechSupply, gridG: G, gridD: D, rho, supplyRate, totalEta };
  } else {
    // 直驱：传动轴（line shaft）摩擦损耗
    const etaTrans = 1 / (1 + 0.08 * n);
    const mechSupply = mechRaw * etaTrans;
    const supplyRate = Math.min(1, mechSupply / (n * FACTORY_MECH_KW || 1));
    const totalEta = getBoilerEta(state) * getSteamEta2(state) * etaTrans;
    return { coalBurned: Math.min(state.coal, (state.jobs.stoker ?? 0) * 5), mechRaw, mechSupply, gridG: 0, gridD: 0, rho: 1, supplyRate, totalEta };
  }
}
```

> **为什么把 ρ 同时用在「发电侧 G」和「供给率」上、但不双重惩罚**：
> 电气化路径里 `G = mechRaw × η₃ × η₄` 已经把煤→电的全部损耗（含 η₄ 输电）算进发电量，
> 而 `mechSupply = G × η₅` 再补电动机损耗。工厂轴端得到的机械能 = `mechSupply`，
> 归一化到 `工厂×60kW` 需求得到 `supplyRate`——**这就是工厂产能的唯一节流**。
> `ρ` 同时作为「电网健康度」输出给 UI 与拉闸惩罚（见 3.2.1），二者同源不重复乘。
> 直驱路径无电网，`ρ=1`、`G/D=0`，工厂只受 `η_trans` 传动损耗约束——与设计 §1.2「瓦特 6 厂直驱反而 2.74%<3.75%」一致。

```ts
// 3.2.1 电网惩罚（ρ 阈值，来自 §3.1）
function applyGridThrottle(rho: number): { outputMul: number; brownout: boolean; blackout: boolean } {
  if (rho >= 1)    return { outputMul: 1,    brownout: false, blackout: false };
  if (rho >= 0.6)  return { outputMul: rho,  brownout: false, blackout: false }; // 全厂降速 ×ρ
  if (rho >= 0.2)  return { outputMul: rho,  brownout: true,  blackout: false }; // 拉闸：r 额外 ×0.7 + 暗角
  return { outputMul: 0.3, brownout: true, blackout: true };                      // 电网崩溃 ×0.3，蒸汽冗余接管
}
```

> ⚠️ **为什么用「全厂降速」而非「部分断电」**（设计 §3.1 原文）：真实电网无法选择性供电给某台机器。
> 降速是连续、平滑、可感知的惩罚——玩家看到产出数字缓慢下滑，立刻去查电网面板，而非突然暴死。

### 3.3 `doTick` 的执行顺序（重要：顺序错会算错账）

```
1  旧岗位产出（伐木/打石/农夫/牧人/织工，E6 起 ×0.2 下限；时代门控）
2  煤/钢产出（矿工、炼钢工；炼钢工耗煤 0.8/秒）
3  能量链推进（calcSupply）：煤耗、机械能产出、电网 G/D/ρ、供给率、总效率
4  工厂产出（6 × 规模系数 × 供给率 × 科技加成 × ρ电气惩罚）；工业品入库
5  蒸汽压力（tickSteam）：司炉工维持上升；自然衰减；档位/喘振判定
6  污染累积（Σ工厂×0.008/s − 治理速率）；卫生因子刷新
7  人口消耗食物（0.2/秒/人）+ 吃粮
8  人口增长（r = 0.02 × 拥挤系数 × 卫生因子 × 食物生存因子；K = 900 + 住宅×200）
9  知识产出（人口 × 0.3 × (1+0.03N)）
10 跃迁条件检查（仅 UI 轮询，tick 不自动跃迁）
```

> ⚠️ **为什么能量链（步骤 3）排在工厂产出（步骤 4）之前、人口（步骤 8）之前**：
> 工厂产能由能量链当帧的供给率决定，必须先算能量再算产出，否则工厂用上一帧的陈旧供给率。
> 人口吃粮（步骤 7）在工程品之前——粮食断供要先于工业化体现，沿用 E1/E2「食物是生存开关」的优先级。
> 污染（步骤 6）在人口增长（步骤 8）之前——卫生因子必须本帧刷新，才能正确进入 r 计算，
> 否则「治理后人口回升」会晚一拍，玩家误以为治理无效（同 E3 贸易排序的历史教训）。

## 四、待拍板 4 项 · 推荐方案

> 每项给推荐与理由。**你只需回「按推荐」或指出要改哪条**，不用逐条写方案。

### 4.1 研究货币命名（知识 vs 研究点）→ **推荐：字段名沿用 `knowledge`，UI 文案 E6 称「知识」**
- 理由：E3 已把研究货币字段定为 `knowledge`；E6-machine.md §6 资源列表明确列「知识」为本代研究货币。
  `E5 研究点`是 era 进展提案里的命名层差异，本质同一资源。沿用 `knowledge` 字段零迁移成本。
- 备选：若坚持 E5 起的「研究点」命名，需新增字段并重命名——徒增迁移风险，不建议。

### 4.2 工厂能耗口径（60kW 轴端 vs 150kW 电网端）→ **推荐：内部统一用 60kW 轴端需求，150kW 仅作电网端展示**
- 理由：§1.2/§11.4 的「工厂耗 60 kW 机械能」是产能计算的真口径；§3.1 的「150 kW」是电网端含电动机/传输开销的读数。
  本计划 3.2 已把两者统一（直驱用 60、电气用 150 进 D 但供给率仍归一到 60），避免双重惩罚。
- 备选：强行两表各算——会导致工厂产能被重复折扣，必须否决。

### 4.3 城市化率「城市人口」口径 → **推荐：U = min(1, 工人住宅承载 / max(population,1))**
- 理由：设计 §4.2 只给「U = 城市人口/总人口」但未定义城市人口。工人住宅提供 K（+200/座），
  是最贴近「城市承载」的可量化来源；U 随住宅建设单调上升，符合「城市化是连续权衡」的设计意图。
- 备选：用「工业岗位人数/总人口」——但前期矿工/司炉工也是城里人，会低估；不推荐。

### 4.4 「分析机」降级后的成本与归属 → **推荐：作为支撑科技，成本并入支撑合计重算（标 TODO(balance)）**
- 理由：2026-09-12 修订已定「分析机」由门槛降为支撑彩蛋（指 E8 信息时代）。
  其成本需补入支撑合计（设计 §11.7 已标 TODO）；不阻塞「电力」门槛，不影响跃迁六项条件。
- 备选：彻底删除——会丢失 E6→E8 的叙事暗线，不建议。
