# E7 · 电子时代（信息时代 / 约 1936–1991）

> 当计算可以被外包给机器，人终于能从微观操作里抬头。
> **这是地面时代的最后一代。** 它的终局不是"更强的计算机"，而是**离开地面**。

---

## 🌟 核心科技：计算机

| 维度 | 内容 |
|---|---|
| **发展方式** | **信息自动化型** —— 用数据购买自动化，逐步交出微观操作 |
| **核心矛盾** | 自动化需要数据，数据需要算力，算力需要能源 → **三重依赖链，任一环断裂则自动化瘫痪** |

**为什么核心矛盾是这个**：E1–E6 里，玩家的瓶颈始终是"人不够 / 物资不够"——瓶颈在**外部世界**。E7 第一次把瓶颈放到**玩家自己的操作**上：文明已经大到一个人管不过来了。计算机的承诺是"把管理外包给机器"，但机器不是免费的——它要数据喂养，要算力运行，要电力驱动。**你越自动化，链条越长，越脆弱。**

**发展方式的独特性**（对比前六代）：

| 时代 | 玩家优化什么 | 瓶颈所在 |
|---|---|---|
| E1 火 | 别让火灭了 | 外部环境 |
| E2 农业 | 攒够过冬的粮 | 外部季节 |
| E3 文字 | 让知识物资流动 | 外部地理 |
| E4 法典 | 扩张与维稳平衡 | 外部规模 |
| E5 印刷术 | 让研究滚雪球 | 外部传播 |
| E6 蒸汽机 | 把煤转成生产力 | 外部能量 |
| **E7 计算机** | **把自己从微观操作中解放出来** | **玩家自身的注意力** |

> **这是全作唯一一个"以玩家自己为瓶颈"的时代。** 前三代的主题是"征服自然"，E7 的主题是"征服复杂度"。它给出 E8 的前提条件：**只有先学会不亲手操船，才可能指挥一支舰队。**

### 1. 三重依赖链（核心机制）

#### 1.1 链条本身

```
   📊 数据  ◀────────  🖥️ 算力  ◀────────  ⚡ 能源
   （货币）             （引擎）              （地基）
      │                    │                    │
   购买自动化          运行自动化           驱动算力
```

**反向依赖（这才是难点）**：

```
   自动化 ──▶ 提升人力效率 ──▶ 更多发电/建造 ──▶ 更多算力 ──▶ 更多数据
```

**闭环成立，但链条每加一环，断点就多一个。** 玩家的整个 E7 都在这条链上找**当前最细的那一环**。

#### 1.2 四层公式（核心，必须能悬停展开）

```
① 能源层
   E_net = E_gen − E_pop − E_industry
   E_gen  = Σ(火电厂 × 15) + Σ(核电站 × 50)
   E_pop  = 人口 × 0.02
   E_industry = 非计算类工业用电（E6 继承）

② 算力层（供需取小 —— 这是三重链的第一道闸门）
   C_inst = Σ(计算中心 × 该世代单机算力)
   C      = min( C_inst , max(0, E_net) / e )
   e = 单算力功耗（随世代下降，见 11.2）

③ 数据层（算力换数据）
   D/s = C_data × k_d × (1 + 联网加成)
   C_data = 分配给"数据处理"的算力
   k_d = 0.06 数据/秒/算力

④ 自动化层（数据换自动化，算力是硬上限）
   N_run = min( N_owned , floor(C_auto / c_a) )
   C_auto = 分配给"自动化运行"的算力
```

**四层各有各的"断裂表现"**：

| 断在哪 | 现象 | 玩家看到什么 |
|---|---|---|
| 能源层断 | `E_net < 0` → 全文明降速 | 电力条变红，所有产出 ×0.5 |
| 算力层断 | `C < C_inst` → 算力被电力卡住 | "装机 800，可用 320 ← 电力不足" |
| 数据层断 | 算力没分给数据 → 数据停增 | 数据条不动，自动化买不起 |
| 自动化层断 | `C_auto < 需求` → 部分自动化停摆 | **降载级联**（见 1.4） |

#### 1.3 为什么用"取小"而不是"加权"

`C = min(C_inst, E_net / e)` 里的 `min` 是**刻意的非平滑设计**。

如果用电力和算力加权求和，玩家永远感觉不到"缺电"，只会感觉"慢一点"。用 `min`，**缺电时算力直接腰斩**——仪表盘上的数字会**跳变**，玩家立刻知道该建电厂了。

> **设计意图**：三重依赖链的价值在于**让玩家感到脆弱**。平滑曲线会让脆弱感消失。

#### 1.4 降载级联（本代最重要的失败状态）

当 `C_auto` 不足以支撑全部已购自动化时，系统按**玩家设定的优先级**依次暂停自动化：

| 优先级 | 默认 | 说明 |
|---|---|---|
| 1（最高，最后停） | 自动调度 | 停了人力会乱，最危险 |
| 2 | 自动建造 | 停了成长放缓，但不崩 |
| 3（最低，最先停） | 自动研究 | 停了只是慢 |

**玩家可自由拖拽排序** —— 这是 E7 里最重要的一个宏观决策：**断电时，你的文明优先保住什么？**

> ⚠️ **注意级联会自我放大**：停掉「自动调度」→ 人力分配混乱 → 发电岗位缺人 → 电力更低 → 更多自动化停摆。
> 这就是"三重依赖链"最残酷的一次教学。设计上**允许它发生**，并在 UI 上用红色箭头明确画出这个正反馈环。

### 2. 自动化系统（核心机制 · 本作最重要的体验升级）

#### 2.1 为什么这是 E7 的灵魂

规格书四层循环理论中，**「微观层自动化」是关键节点**：

```
   宏观层（战略）      ← 玩家永远应该待在这一层
        ▲
        │  自动化把玩家往上推
        │
   中观层（规划）
        ▲
        │
   微观层（操作）      ← E1–E6 里玩家 80% 的时间在这里
        ▲
        │
   基础层（资源）
```

**E1–E6 的放置游戏通病**：时代越往后，玩家要点的东西越多，**操作量线性上涨**，最后从"策略游戏"退化成"点击苦力"。

**E7 用自动化把这条曲线掰回来**：不是让你少玩，而是让你**换一层玩**。微观操作交给 AI 助手，你的注意力上移到"自动化之间如何配比、断电时保谁、核电要不要上"。

> **一句话**：E7 不是"更多按钮"，是"更少的按钮，更重的每一个"。

#### 2.2 分阶段解放（三条线 × 三级）

**只能按顺序买**：调度 → 建造 → 研究。这个顺序**不可跳过**，且每级的"解放程度"有质的差别。

##### 线 A · 自动调度（Auto-Assign）—— 先解放"分人"

| 等级 | 数据成本 | 占用算力 | 效果 | 玩家被解放了什么 |
|---|---|---|---|---|
| **Lv1** | 150 | 2 | 自动补足各岗位的人力缺口（保底：不让人力闲置） | 不用再手动点 +1/−1 |
| **Lv2** | 1,200 | 6 | 按**边际收益**最优分配（每 5 秒重算一次） | 不用再算"哪个岗划算" |
| **Lv3** | 9,000 | 18 | **预防性再平衡**：提前 30 秒预测缺口并预调 | 不用再盯变化 |

##### 线 B · 自动建造（Auto-Build）—— 再解放"盖房"

| 等级 | 数据成本 | 占用算力 | 效果 | 玩家被解放了什么 |
|---|---|---|---|---|
| **Lv1** | 600 | 4 | 自动建造**最便宜**的可建建筑 | 不用再逐个点建造 |
| **Lv2** | 4,800 | 12 | 按**收益/成本比**排序建 | 不用再算性价比 |
| **Lv3** | 36,000 | 36 | 自动**预留成本** + 建造队列（可排队 10 项） | 可以离开键盘 |

##### 线 C · 自动研究（Auto-Research）—— 最后解放"想"

| 等级 | 数据成本 | 占用算力 | 效果 | 玩家被解放了什么 |
|---|---|---|---|---|
| **Lv1** | 2,400 | 8 | 自动研究**当前最便宜**的科技 | 不用再点科技 |
| **Lv2** | 19,000 | 24 | 按**时代目标路径**优先（自动偏向门槛科技） | 不用再规划路线 |
| **Lv3** | 150,000 | 72 | **全局最优顺序** + 预测（模拟未来 5 项科技的收益） | 可以只做宏观决定 |

**全三线满级合计**：数据 223,150 / 占用算力 **182**

> **为什么"先分人、再盖房、最后研究"是这个顺序**：
> 分配的决策频率最高（每几秒一次）→ 先自动化收益最大；
> 建造频率中等（每分钟级）→ 其次；
> 研究频率最低（每几分钟一次）→ 最后。
> **按操作频率排序解放，而不是按重要性。** 这是"体验升级"的工程化表达——玩家最先感到轻松。

#### 2.3 自化的三条硬约束（防止它变成"一键通关"）

| 约束 | 机制 | 为什么 |
|---|---|---|
| **算力上限** | 每条线每级都占算力，`N_run ≤ C_auto / c_a` | 自动化不是免费的，它吃掉你本可以用来产数据的算力 |
| **数据货币** | 只能"买"，不能"解锁" | 数据本身要靠算力产，形成正反馈但也形成前期门槛 |
| **不处理危机** | 自动化**不会**应对随机事件（事故、断电、饥荒） | 自动化只做"常规操作"，**危机永远需要人** |

> **第三条最关键**：如果自动化能处理一切，游戏就结束了。设计上明确画一条线——**自动化管常规，玩家管异常**。玩家的注意力从"重复劳动"转移到"例外处理"，这正是 E7 想表达的文明状态。

### 3. 核能（新系统 · 高风险高回报）

#### 3.1 为什么需要核能

算力增长是指数级的，火电是线性的。到中后期：

| 方案 | 支撑 1000 算力所需 | 占地/成本 |
|---|---|---|
| 火电厂（15 电力/秒，单机算力功耗 0.08） | **6 座** | 还烧煤，有污染 |
| 核电站（50 电力/秒） | **2 座** | 但有事故风险 |

到微处理器世代（单算力功耗 0.03），2000 算力需 60 电力/秒：
- 火电：**4 座**
- 核电：**2 座**（还余量）

**核能是唯一能让"算力瓶颈"真正松开的选项。** 这就是它的"高回报"。

#### 3.2 风险机制

```
单座核电站堆芯风险累积速率
  = 0.0015 /秒 × (1 + 废料堆积系数 0–2.0) × (1 − 维护覆盖率 0–1)

维护覆盖率 = 核工程师数 / (核电站数 × 8)，上限 1.0

累积风险 ≥ 1.0 → 触发事故
```

**无维护时**：`1 / 0.0015 ≈ 667 秒 ≈ 11 分钟`必出事 —— 这是刻意的**高压计时器**。
**满维护时**：0.0015 × (1+0) × (1−1) = **0**，安全。

#### 3.3 事故后果（分级）

| 等级 | 触发条件 | 后果 |
|---|---|---|
| **轻微泄漏** | 风险 1.0–1.5 | 该电站停机 120 秒；周边产出 −30% ×300 秒 |
| **堆芯熔毁** | 风险 1.5–2.5 | 该电站**永久损毁**；周边产出 −60% ×600 秒；人口 −5% |
| **灾难** | 风险 ≥ 2.5 | 电站损毁 + 连锁（相邻电站风险 +0.5）+ 该区域 **K 永久 −10%** |

> **核事故的 K 惩罚是永久的** —— 这是本条设计的关键。玩家会**长期**记得那次事故，而不是重建成原样就忘了。文明付出了不可逆的代价。

#### 3.4 废料：延迟的代价

核电站每秒产生 `0.002` 核废料，累积不清则：
- `废料堆积系数 = min(2.0, 废料总量 / 50)` → 直接抬高所有核电站的风险
- 废料还占用周边 K（每 10 废料 → 该区 K −1）

**所以核电不是"建了就完事"**——它要求玩家持续投入（核工程师岗位 + 后处理厂建筑 + 安全壳科技）。**高回报必须用持续的高维护来换。**

#### 3.5 史实锚点

| 事件 | 年代 | 用于设计 |
|---|---|---|
| 芝加哥一号堆 CP-1 首次自持链式反应（费米主持） | **1942-12-02** | 核裂变科技的解锁条件 |
| 三位一体核试验（人类首次核爆） | **1945-07-16** | 核能的"武器化"分支（本作不展开，仅作背景） |
| 奥布宁斯克核电站并网，**装机 5 MW**，世界首座商用核电站 | **1954-06-27** | 核电站建筑的解锁 |
| 三里岛事故 | **1979** | 「三里岛教训」效率科技（事故损失 −30%） |
| 切尔诺贝利事故 | **1986** | 灾难级事故的参考模型 |

> ⚠️ **争议标注**：核电站的事故概率在真实世界中**业界估算分歧极大**（从 1/10⁴ 堆年 到 1/10⁶ 堆年 不等，取决于是否计入设计基准外事件）。
> 本作取 **0.0015/秒（约 11 分钟无维护）** 是**游戏性取值，非史实推演**，目的是制造持续压力。**不要**把它当成对现实核电安全性的判断。

### 4. 联网与发射（新系统 · 两个新动词）

#### 4.1 联网（Network）—— 让算力突破单点上限

**史实锚点**：ARPANET 于 **1969** 年首次连接四个节点（UCLA、SRI、UCSB、犹他大学），是**世界上第一个运营的分组交换网络**；万维网由 Tim Berners-Lee 于 **1989 年 3 月**在 CERN 提交提案。

**机制**：网络节点建筑可连接分散的计算中心。

```
联网加成 = 0.15 × √(联网节点数)        节点数 1–16

数据产出   × (1 + 联网加成)
算力上限   = Σ各中心算力 × (1 + 0.5 × 联网加成)
```

| 节点数 | 联网加成 | 数据 | 算力上限 |
|---|---|---|---|
| 0 | 0 | ×1.00 | ×1.00 |
| 1 | 0.15 | ×1.15 | ×1.08 |
| 4 | 0.30 | ×1.30 | ×1.15 |
| 9 | 0.45 | ×1.45 | ×1.23 |
| 16 | 0.60 | ×1.60 | ×1.30 |

**为什么用 √**：网络的价值随节点数增长，但**每新增一个节点的边际价值递减**——因为已连接的节点越多，新增的那条链路带来的"新可达对"占比越小。这是**梅特卡夫定律（n²）的理性衰减版**——真用 n² 会爆炸，√n 保持"联网值得做，但别指望无限叠"。

> **联网的"质"作用**：联网是**跨站点共享算力**的前提。没有联网，每个计算中心的算力只能自己用；有了联网，全文明的算力汇成一个池子 —— 这是自动化能规模化运行的技术前提。

#### 4.2 发射（Launch）—— 通往 E8 的唯一出口

E7 的第三个新动词，也是**整个地面时代的终点**。

| 里程碑 | 成本 | 效果 | 史实锚点 |
|---|---|---|---|
| **1. 发射场建成** | 钢铁 8,000 + 持续 300 电力/秒 ×120 秒 | 解锁发射任务队列 | — |
| **2. 卫星入轨** | 钢铁 2,000 + 占用算力 500 ×300 秒 | 联网节点 +1；解锁「卫星通信」科技 | 斯普特尼克 1 号，**1957-10-04**，拜科努尔，人类首颗入轨人造卫星 |
| **3. 载人航天** | 钢铁 5,000 + 数据 50,000 + 人口 −1 | 触发"文明里程碑"事件；人口管理因子永久 +0.2 | 东方一号，**1961-04-12**，加加林，人类首次载人轨道飞行 |
| **4. 月球着陆** | 钢铁 15,000 + 数据 200,000 + 算力 800 ×600 秒 | 解锁「轨道建造」的研究前置 | 阿波罗 11 号，**1969-07-20** |
| **5. 轨道建造** | 钢铁 20,000 + 数据 500,000 + 算力 1,000 ×600 秒 | **门槛科技完成 → 解锁 E8 跃迁** | — |

**发射的机制特色**：每次发射都**占用大量算力**（500–1000）持续数百秒。这意味着——

> **发射 = 主动制造一次算力危机。**
> 玩家必须在"继续自动化"和"向上发射"之间取舍：把 1000 算力交给火箭 10 分钟，自动化就得降载。
> **这是 E7 的终局考验：你准备好为了离开地面，暂时放弃地面的舒适了吗？**

**斯普特尼克冲击（事件）**：首次成功入轨后，触发一次**全文明事件**——「斯普特尼克时刻」：全科技研究速度 +25%，持续 600 秒（灵感来自 1957 年苏联发射后美国掀起的科研追赶）。⚠️ 事件效果为**游戏设计取值**。

### 5. 计算机 — 人口 — 产出 的咬合

```
        💻 计算机（核心 · 自动化引擎）
        │ 提供算力 → 生产数据 → 购买自动化
        │ 自动化 → 解放人力 → 人力转向更高价值岗位
        │ 自动化管理因子 → 人口增长率 r ↑
        ▼
   👥 人口（引擎 · 群体增长，逻辑斯蒂）
        │ 人口 = 人力上限
        │ 人口 = 经验来源
        │ 人口 = 生活用电消耗（新：人口第一次成为"能耗负担"）
        ▼
   ⚡ 电力 / 🔩 钢铁 / 📊 数据（产出）
        │ 电力 → 驱动算力（回到顶层）
        ▼
   🚀 发射场 / 轨道建造（出口）
```

**闭环（正向）**：
计算机 → 算力 → 数据 → 自动化 → 人力解放 → 更多发电与建设 → 更多算力 → …（指数螺旋）

**闭环（负向，本代特征）**：
自动化↑ → 算力需求↑ → 电力需求↑ → **若发电跟不上 → 降载级联 → 自动化停摆 → 人力混乱 → 发电更少**（死亡螺旋）

> **与前六代最大的区别**：E1–E6 的负反馈来自**自然**（火灭、冬天、资源枯竭），E7 的负反馈来自**玩家自己的成功**。
> **你越成功，链条越长，越容易崩。** 这是"信息自动化型"独有的体验。

### 6. 资源集

**两个特殊项（不计入资源列表，是本代的仪表盘）**：

- **🖥️ 算力（Compute）** —— **容量型数值**，不是流量。它有"装机上限 `C_inst`"和"实际可用 `C`"两个值。**这是 E7 的核心仪表盘，地位等同 E1 的火种。**
- **☢️ 堆芯风险（Core Risk）** —— 0–2.5 的累积值，超过 1.0 触发事故。**第二个仪表盘。**
- **🔌 自动化槽位** —— 已购自动化线的运行状态（运行/降载/停摆）

> **数据 vs 算力的分工（关键设计）**：
> **数据是"花的"，算力是"占的"。**
> 数据一次性花掉买自动化；算力被自动化**持续占用**。
> 所以"买得起"和"跑得动"是两件事 —— **这正是三重依赖链在玩家操作层的体现**。

**六座建筑，与限制一一对应**：

| 限制 | 建筑 |
|---|---|
| 算力不足 | 🏢 计算中心 |
| 散热不足（算力上不去） | ❄️ 冷却塔 |
| 电力不足 | ⚛️ 核电站 |
| 单站点上限 | 🗼 网络节点 |
| 人口上限 | 🏙️ 城市住宅区 |
| **出口** | 🏗️ 发射场 |

> **❄️ 冷却塔为什么必须有**：真实历史里，散热是早期计算机的核心工程问题 —— ENIAC 的 18,000 支电子管本身就是一个巨型发热体；后来的 CDC 6600（1964）直接使用氟利昂冷却。设计上把它抽象为"冷却系数"，**让"装机算力"不等于"可用算力"** —— 这是算力层的第二道闸门。

> **⚠️ 争议标注**：**ENIAC 是否是"第一台电子计算机"存在学术争议** —— ABC（Atanasoff–Berry Computer, 1942）、Z3（Zuse, 1941）、Colossus（1943）都在某一方面更早。ENIAC 的公认地位是「第一台**可编程、电子式、通用数字**计算机」（`first programmable, electronic, general-purpose digital computer`），其特殊性在于**同时满足全部四项**。本作采用这一限定表述。

**"计算机"降到 0.60 但与其它旧核心有本质区别**：它是**唯一一个降权后仍保留"功能"而非仅"加成"的旧核心**。

> **为什么**：如果自动化在 E8 失效，玩家会被**打回微观操作**——这是最糟糕的体验倒退（"我辛苦解放的注意力又被收走了"）。
> 所以 E7 的核心科技做了特殊处理：**加成可以衰减，自动化本身必须保留**。

**E7 专属的跨时代资源**：**数据** 保留为 E8 的通用货币之一（E8 中用于"殖民地指令"），**铀矿** 保留（核能基线）。

#### 11.3 人口（逻辑斯蒂增长 · r 受自动化程度影响）

**公式**（沿用 E1，仅改 r 与 K 的构成）：

```
人口增长速率 = r × P × (1 − P / K) × 食物因子

r = 基础增长率 × 能源因子 × 自动化管理因子      ← 本代新增第二项
K = 基础上限 + Σ城市住宅区容量 + 自动化密度加成 − 核废料区惩罚
```

| 项 | 值 |
|---|---|
| 基础增长率 | **0.004 /秒**（比 E1 低，因基数大） |
| K 基础上限 | 320 |
| 每座城市住宅区 | **K +50** |
| 食物消耗 | 0.015 /秒/人 |
| 经验产出 | **0.25 /秒/人** |

**能源因子**（电力成为人口增长的环境条件）

| 电力状况 | 能源因子 |
|---|---|
| 充裕（`E_net > 需求 × 1.5`） | **1.0** |
| 正常 | 0.8 |
| 紧张（`E_net < 需求`） | 0.4 |
| **断电（`E_net ≤ 0`）** | **0**（人口停止增长） |

**自动化管理因子**（本代的核心设计点）

```
自动化管理因子 = 1 + 0.20 × 自动调度等级
                   + 0.10 × 自动建造等级
                   + 0.10 × 自动研究等级
```

| 自动化状态 | 管理因子 | 说明 |
|---|---|---|
| 全无 | **1.00** | 320 人口已接近人工管理极限 |
| 调度 Lv1 | 1.20 | 人力不再闲置 |
| 三线 Lv1 | 1.40 | 常规操作全部移交 |
| 三线 Lv3 | **2.20** | 文明几乎全自动运转 |

> **为什么自动化影响 r 而不是直接加人口**：自动化不是"多生人"，而是**让管理效率提升** —— 粮食调配、住房分配、公共卫生调度都更精准，于是人口能以更快的速率逼近上限。
> **这是"质变"而非"量变"**：它改的是增长**速率**，不是**上限**。上限仍由 K（住房）决定，玩家必须继续建住宅区。

**曲线示例**（K = 520，能源充裕，三线 Lv3 → r = 0.004 × 1.0 × 2.20 = 0.0088）

| 人口 P | 增长速率 | 阶段 |
|---|---|---|
| 320 | 0.56 /秒 | 起步 |
| 520 | 0.00 /秒 | 到顶 |

> 到顶了怎么办？→ **建城市住宅区抬高 K**。这与 E1 完全同构，玩家一看就懂。

| **人工录入** | 人力 × 0.15 | 不受算力约束，**前期唯一出路**；后期完全被自动化算力淘汰 |
| **计算中心** | `算力 × 0.06 × 联网加成` | 无上限，但受三重链约束 |

> **为什么保留"人工录入"这个低效岗位**：它是 0:00–0:45 的**唯一经济来源**，让玩家在还没有计算机时就能开始攒钱。
> 更重要的是——**它会在中后期被自动化彻底取代**。玩家会亲眼看到：20 个录入员（3 数据/秒）被一台计算中心（同电力下 20 数据/秒）碾压。
> **这是"计算机取代人力"这个文明主题最直观的一次演出**，不需要任何台词。

#### 11.5 平衡验算

**算力 — 电力 — 自动化的三重平衡**（取中后期节点：世代 3，单算力功耗 0.08）

| 场景 | 算力需求 | 电力需求（算力） | 生活用电（600 人） | 总电力 | 供给方案 |
|---|---|---|---|---|---|
| 三线 Lv1（26 算力） | 26 | 2.1 | 12.0 | **14.1** | 1 座火电（15）✅ |
| 三线 Lv2（78 算力） | 78 | 6.2 | 12.0 | **18.2** | 2 座火电（30）✅ |
| 三线 Lv3（182 算力） | 182 | 14.6 | 12.0 | **26.6** | 2 座火电（30）⚠️ 无余量 |
| **三线 Lv3 + 1000 算力产数据** | **1,182** | **94.6** | 12.0 | **106.6** | 火电需 **8 座**；**核电仅需 3 座** ✅ |

> **核能的价值在此量化**：106.6 电力/秒用火电要 8 座（占 8 个建筑位 + 8 份煤耗），用核电只要 **2.1 座**。
> **当算力需求跨过 1000 这道坎，核电从"可选"变成"唯一解"。** 这就是"大幅缓解算力瓶颈"的具体含义。

**数据 — 成本验算**

| 自动化线 | 满级累计数据成本 |
|---|---|
| 自动调度（150 + 1,200 + 9,000） | 10,350 |
| 自动建造（600 + 4,800 + 36,000） | 41,400 |
| 自动研究（2,400 + 19,000 + 150,000） | 171,400 |
| **三线满级合计** | **223,150** |
| + 自动化相关效率科技（OS / MIS / 机器人 / 专家系统 / AI） | ≈ 60,000 |
| **自动化全解锁总计** | **≈ 283,000 数据** |

**数据产出曲线**（估算，含联网加成）

| 时段 | 时长 | 算力（均值） | 数据/秒（均值） | 累计数据 |
|---|---|---|---|---|
| 0:00–0:45 人工录入期 | 2,700 s | 0 | 2.0 | **5,400** |
| 0:45–2:30 首座计算中心 | 6,300 s | 30 | 2.5 | **15,750** |
| 2:30–4:30 晶体管化 | 7,200 s | 120 | 9.0 | **64,800** |
| 4:30–6:30 集成化 + 联网 | 7,200 s | 450 | 35 | **252,000** |
| 6:30–9:00 核电 + 自动化全开 | 9,000 s | 1,500 | 115 | **1,035,000** |
| **合计** | 32,400 s | — | — | **≈ 1,373,000** |

**取舍是否成立**：
- 自动化全解锁需 **283,000**（可轻松达成 ✅）
- 但**发射链**需要数据 **750,000**（卫星 0 + 载人 50,000 + 月球 200,000 + 轨道 500,000）
- 两者相加 **≈ 1,033,000**，占总产出 **75%**
- 剩余 25%（约 340,000）供**效率科技**与**容错**（事故重建、发射失败重试）

> **结论**：玩家**必须**在"先全开自动化"和"先攒发射"之间做取舍。
> 若前期过度投入自动化 → 后期数据虽多但发射来不及；若过早发射 → 自动化不足，人力管不过来，产出上不去。
> **这正是 E7 的核心取舍，与 E1 的"先攀科技还是先堆人头"同构。**

#### 11.8 跃迁条件（E7 → E8）


### 12. 9 小时节奏时间线

| 时段 | 玩家在做什么 | 人口 | 算力 | 自动化状态 |
|---|---|---|---|---|
| **0:00–0:45** | 派数据录入员攒数据；研究图灵机 → 存储程序架构 | 320 → 340 | 0 | 无 |
| **0:45–2:00** | 建首座计算中心；买**自动调度 Lv1** —— 第一次交出微观操作 | 340 → 400 | 20 → 40 | 调度 Lv1 |
| **2:00–3:30** | 晶体管化；建冷却塔；买**自动建造 Lv1** —— 建筑开始自动排队 | 400 → 480 | 60 → 130 | 调度 Lv1 + 建造 Lv1 |

| **5:00–6:30** | 核裂变 → **首座核电站**；派核工程师；**第一次堆芯风险警报** | 560 → 650 | 420 → 800 | 三条 Lv2 |

**体验曲线设计**：

| 时间点 | 设计事件 | 目的 |
|---|---|---|
| **0:00–0:45** | 纯手工录入数据，慢得令人焦躁 | **制造"我需要机器"的渴望** —— 没有这段，自动化不会有快感 |
| **0:45** | **第一次自动化**（自动调度 Lv1） | **全作最强的正反馈时刻** |
| **2:00** | 自动建造上线 | 玩家开始敢于离开键盘 |
| **3:30** | 自动研究上线 | 三条线齐备 —— **"我终于可以只做宏观决策了"** |
| **5:00** | 核电站 + 第一声风险警报 | **引入新的恐惧**：自动化带来的能源，本身是危险的 |
| **6:30** | **降载级联** | **本代的核心危机体验**：三重链断裂的完整演示 |
| **8:00** | 发射占用算力，自动化被迫降载 | **终局取舍**：为了上天，暂时放弃地面的舒适 |
| **8:45** | 轨道建造完成 | 出口打开 |

> **关键节奏设计**：E7 的**前 45 分钟故意做得很难受**（纯手工、慢、无聊）。
> 这不是设计缺陷，而是**必要的铺垫** —— 玩家必须先体验"没有自动化的痛苦"，才会在 0:45 买到第一级的瞬间产生**真正的解脱感**。
> 这也让 E7 与 E6 的"优化能量效率"在**手感上**彻底区分开：E6 是"算得更多"，E7 是"终于不用算了"。

| **❓ 悬停解释** | 每个数字都可悬停：*"可用算力 182：装机 420，受电力限制（可用电力 14.6 ÷ 单算力功耗 0.08 = 182）"* —— 落实"所有数字可解释"铁律 |
| **🎯 E8 进度环** | 底部常驻"离开地面"进度：显示 6 项跃迁条件的完成度（含之前所有时代的门槛） |

**三个层次的视觉注意力分配**（关键）：

```
上方 1/4 屏幕  →  三重依赖链环图（宏观状态，一眼看全局）
中部 1/2 屏幕  →  自动化面板 + 降载优先级（玩家真正操作的地方）
下方 1/4 屏幕  →  发射 / E8 进度（长期目标）
```

> **E1–E6 的 UI 是"一堆岗位 + 一堆建筑"，玩家要在几十个按钮里找。**
> **E7 的 UI 应该只有三个自动化卡片在中间。** 因为到了这个时代，**文明已经大到一个屏幕装不下了** —— UI 本身也必须"被自动化"。

### 14. 与 E8 的衔接

#### 14.1 E7 留下的三样东西

| 遗产 | 在 E8 中的作用 |
|---|---|
| **自动化系统** | E8 的**舰船调度 / 殖民地管理 / 星际航线排班**全部建立在 E7 的自动化框架上。E8 玩家**永远不需要手动分配人力** —— 这是 E7 送给 E8 的最大礼物 |
| **数据货币** | 保留为 E8 的通用货币（用于"殖民地指令"）；数据在 E8 中由**星舰上的计算单元**产出 |
| **核能基线** | 核电站作为星际殖民地的基础能源；核聚变研究（E7 未完成）在 E8 开花 |

#### 14.2 跃迁时的交接演出

| 变化 | 说明 |
|---|---|
| 三重依赖链**不再断裂** | 星舰自带独立能源与算力 —— 三重链在 E7 是矛盾，在 E8 是**已解决的遗产** |
| 电力**退出主舞台** | 转为"殖民地基础设施"折叠区（降级而非取消） |
| 核能**转为基线** | 从"高风险高回报选项"降为"默认能源"，事故风险大幅降低（安全技术成熟） |
| 算力**转为飞船属性** | 从"文明级容量"变为"每艘星舰的独立属性" |
| **自动化面板保留** | 但默认全部满级运行 —— 玩家不再需要配置它 |
| 解锁**星图 / 航线 / 殖民地** | E8 的核心机制登场 |
| 人口模型**保留** | 逻辑斯蒂增长是通用机制，在 E8 中裂变为"多殖民地并行增长" |

#### 14.3 交接提示文案

> **跃迁弹窗**：
> *"地面时代结束了。*
> *从现在起，你不再需要亲手分配任何一个人力 —— 那些在二十世纪被写下的自动化规则，会跟着你的舰队一起离开。*
> *电力不再是你的枷锁，核裂变不再是你的赌注。*
> *但它们都还在运转 —— 在你身后，在这颗蓝色的星球上。*
> ***第一次，你可以只看着星星。***"

#### 14.4 一条明确留给 E8 的钩子

E7 中**「核聚变研究」是一项"永远不会完成"的科技**：

- 它可以被研究，但研究完成后**没有任何即时效果**
- 描述文字只有一行：*"理论上可行。需要的能量，这颗行星给不了。"*
- 进入 E8 后，它自动转化为**聚变反应堆**的前置

> **设计意图**：让玩家在 E7 结束时**已经知道下一代的钥匙长什么样**，但**够不到**。
> 这是"门槛科技 = 下一代核心科技"原则的**情感版** —— 不只是机制上的衔接，而是**让玩家带着一个未解答的问题离开地面时代。**
