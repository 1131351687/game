## 二、任务分解

### T1 · 数据层（新建 `src/data/`）

> 纯数据，零逻辑。所有数值来自设计文档 11 节。

- [ ] **T1.1 资源配置** `src/data/resources.ts`
  - 5 项：食物 🍖 / 木材 🪵 / 石头 🪨 / 经验 💡 / 人口 👥
  - 字段：`id, name, icon, category, unlockCondition`

- [ ] **T1.2 岗位配置** `src/data/jobs.ts`
  - 采集者 0.5 食物/s｜伐木者 0.4 木材/s｜打石者 0.3 石头/s｜猎人 1.2 食物/s（需工具世代 ≥1）
  - 字段：`id, name, icon, requires, outputResource, outputRate`

- [ ] **T1.3 建筑配置** `src/data/buildings.ts`
  - 住所（K +4）｜火塘（火种衰减 −20%）｜作坊（工具世代效果 +20%）
  - 字段：`id, name, icon, cost, effects, requires`

- [ ] **T1.4 科技树配置** `src/data/techs.ts` ← **本任务最重**
  - 20 项，含 `branch` 字段标记所属分支（core / fire / tool / society / gate）
  - 字段：`id, name, branch, cost, type(解锁|质变|数值|跃迁), effects, requires, unlocks, position{x,y}`
  - `position` 供科技树界面直接布局用

- [ ] **T1.5 常量表** `src/data/constants.ts`
  - 火种档位阈值与火源因子（0/0.5/1.0/1.25）
  - 工具世代倍率（1.0 / 1.4 / 1.96 / 3.14）
  - 人口模型参数（基础增长率 0.02、K 基础上限 4、食物消耗 0.2、经验产出 0.12）
  - 跃迁条件（食物 ≥300、住所 ≥3、人口 ≥15）

**验收**：`pnpm tsc --noEmit` 通过；数据表项数与设计文档一致（20 科技 / 5 资源 / 4 岗位 / 3 建筑）。

### T2 · 引擎层（重写 `src/game/engine.ts`）

> 纯函数优先，便于单测。

- [ ] **T2.1 火种系统**
  - `tickFire(state, dt)`：按 2.0/秒 衰减；木材投入 +6/单位
  - `getFireTier(fireValue)`：返回 熄灭/微弱/稳定/旺盛
  - `getFireFactor(tier)`：返回 0 / 0.5 / 1.0 / 1.25
  - **验收**：火种归零时增长停止且人口按 0.5/秒 下降

- [ ] **T2.2 逻辑斯蒂人口模型**
  - `calcPopulationGrowth(P, K, fireFactor, foodFactor, dt)`
  - 公式：`r × P × (1 − P/K) × 食物因子`，其中 `r = 0.02 × 火源因子`
  - **验收**：K=20 时，P=10 增长率最高；P=20 时归零（S 形曲线）

- [ ] **T2.3 资源产出计算**
  - `calcJobOutput(jobId, count, toolTier, workshopBonus)`
  - `calcResourceOutput(resourceId, state)`：汇总所有岗位 + 加成
  - **验收**：猎人在工具世代 1 时产出 1.2 食物/秒；世代 4 时 3.77

- [ ] **T2.4 经验产出**
  - `calcExperienceOutput(population)`：`人口 × 0.12 × (1 + 火把加成)`
  - **验收**：20 人时产出 2.4 经验/秒（未点「火把」）

- [ ] **T2.5 科技树引擎**
  - `canResearch(techId, state)`：返回 `{ok, reason}`，reason 用于 UI 显示"为什么不能研究"
  - `unlockTech(techId)`：扣经验 + 应用 effects + 触发 unlocks
  - `applyTechEffects(state)`：重新计算所有加成
  - **验收**：前置未满足时 `canResearch` 返回明确的 reason 字符串

**验收（整体）**：编写 `engine.test.ts`，覆盖率 ≥ 80%。

### T3 · 系统层

- [ ] **T3.1 研究队列**
  - `queue: string[]`（科技 id 列表，长度上限 5）
  - `enqueue(techId)` / `dequeue(index)` / `reorder(from, to)`
  - 队列首位自动消耗经验解锁；经验不足则暂停
  - **验收**：队列按顺序自动执行；空队列时触发提示

- [ ] **T3.2 离线收益**
  - 记录 `lastActiveAt`；重新打开时计算离线时长
  - 按 **50% 效率**推进，上限 **8 小时**
  - 按队列顺序结算科技，剩余时间结算资源
  - **验收**：模拟离线 2 小时 → 完成约 1 小时等效研究 + 资源增长
  - **验收**：离线提示显示"离线 X 小时，完成了 N 项研究"

- [ ] **T3.3 时代跃迁判定**
  - `canAdvance(state)`：检查四条件（植物栽培已研究 / 食物 ≥300 / 住所 ≥3 / 人口 ≥15）
  - 满足后显示"迈向定居"按钮（E1 内为**终点展示**，点击后播放结算）
  - **验收**：条件未满足时按钮灰显，并提示缺哪一项

- [ ] **T3.4 存档**
  - 带 `version` 字段；`SAVE_KEY = 'civilis_save'`
  - 自动存档（每 5 秒 longLoop）+ 关键操作立即存档
  - **验收**：刷新页面后火种值、人口、科技树进度、队列全部恢复

## 三、依赖顺序

```
T1 数据层
   │
   ├──▶ T2 引擎层 ──┬──▶ T3 系统层 ──▶ T4 UI 层
   │                │
   │                └──▶ T6 配平（需引擎 + UI 就绪）
   │
   └──▶ T5 清理（可随时做）
```

**推荐执行顺序**：T1 → T2 → T5 → T3 → T4 → T6

> T5 提前到 T3 之前，是为了先清掉旧内容，避免在错误的基础上做 UI。

## 五、开发注意事项

1. **火种是本代主角**，UI 上必须最醒目——它是玩家最需要盯着的数值
2. **不要引入 sqrt 递减**：E1 用线性，递减从 E3 开始（设计文档已明确）
3. **研究队列是硬需求**：没有它就不是挂机游戏
4. **科技树界面是核心体验载体**，值得花最多时间打磨
5. **不确定的数值标 TODO**，实装后再校准，不要在设计阶段纠结
