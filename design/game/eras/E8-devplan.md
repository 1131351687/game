# E8 信息时代 · 开发任务清单

> **来源**：[`E8-information.md`](./E8-information.md)（设计规格，1019 行）＋ 代码现实 `demo/src/{game/engine.ts,state/store.ts,game/transition.ts,data/constants.ts}`
> **状态**：📐 **实施级规格草稿**（待拍板 7 项的推荐方案已附，拍板后按第八节工作块开工）
> **目标**：把 E8 实装为可玩的**终局一代**，且**不破坏 E1/E2（及未来 E3–E7）的既有基线**
> **基线**：`demo/` 当前已实装 E1 + E2，`tsc` 0 error；`autoplay beeline` 1163s / `autoplay e2` 1920s
> 为铁律守门值。**本代是末代**：没有"跃迁到下一代"，只有"现代终局条件（§11.8 六项）"与"通关演出（§14.3）"。
>
> **本代的独特之处**：E8 是**全作唯一一个"以玩家自己的操作为瓶颈"的时代**——核心矛盾从"东西不够"
> 转为"东西太多、连得太紧"（§4.3）。它一次性引入 ① 三重依赖链（自动化←数据←算力←电力）② 算力/数据/自动化三线
> ③ 降载级联（本代核心危机）④ 半导体成本指数下降（摩尔式）⑤ 核电高风险高回报 ⑥ 网络与全球化
> ⑦ 发射作为历史演出（非跃迁出口）。难度体量与 E3 同级，必须按节推进。

## ⚠️ 铁律（落文，全程遵守）

- **每代新动词**：本代新动词 = **计算 / 联网 / 自动化**（对应三件套 计算机/半导体/网络）。
- **跃迁只新增不重置**：E8 是末代，无跃迁出口；`transition.ts` 的"只新增不重置"在 E8 体现为
  「进入新时代（若有）资源原样带过」——本代内部不重置任何前代状态。
- **岗位可退役进阶**：E8 不强制退役任何岗位；`数据录入员` 由算力产出**自然淘汰**（设计意图，非硬退役）。
- **不设时长目标**：节奏由终局条件与自动化上线节奏自然决定（§12），不做小时级规划。
- **数字可解释**：每个仪表盘数字都能悬停展开来源（§13 悬停解释）。
- **所有新机制时代门控**：E8 全部计算在 `state.era === 'E8'`（或 `>= 'E8'`）分支内；E1/E2 的
  `tick/产出/人口` 路径字面上不得改变（守门测试见 T5）。

### T2 · 引擎层（`engine.ts`，纯函数优先，全部时代门控）

> ⚠️ **铁律：所有 E8 新机制必须 `state.era === 'E8'` 门控**，否则污染 E1/E2 基线（1163s/1920s）与 SSR 字节一致性。

- [ ] **T2.1 电力与算力（三重依赖链前两道闸门）** ← 本代核心
  - `getPowerNet(state)` = `E_gen(火电×15 + 核电×50) − E_pop(人口×0.02) − E_industry(E6 继承工业电)`
  - `getComputeTier(state)`：取已研究科技中的最高算力世代（存储程序架构=1 … 微处理器=4）
  - `getComputeInstalled(state)` = `Σ计算中心 × 单机算力(世代) × (1+冷却系数+联网半加成)`
  - `getComputeAvailable(state)` = `min(装机, max(0, E_net)/e) − 发射占用 − 程序员占用`；
    **缺电时数字跳变（用 min 非平滑）**
  - **验收**：`E_net < 0` 时 `getComputeAvailable` 直接腰斩；E1/E2 的 `tick` 路径不进入这些函数
- [ ] **T2.2 数据产出（双源）**
  - `getDataRate(state)` = `(数据录入员×0.15 + C_data×k_d) × (1 + 联网加成)`，
    其中 `C_data = getComputeAvailable × computeDataShare`（玩家分配的算力占比）
  - `computeDataShare` 为玩家滑块（默认 0.5，`TODO(balance)`）；人工录入不受算力约束（前期唯一出路）
  - **验收**：无计算中心时数据仅来自录入员；有计算中心后人工占比迅速被碾压（设计 §11.4 演出）
- [ ] **T2.3 降载级联（本代最重要失败状态）** ← 本任务最重
  - `runLoadShedding(state, cAuto)`：按玩家 `autoPriority` 顺序，贪心分配 `cAuto` 给各拥有线；
    每条线的 `c_a(等级)` 得不到满足 → 该线「停摆」，满足 →「运行」，中间态「降载」
  - 级联放大：调度线停摆 → `自动化管理因子` 失去其贡献 → 人口 r 下降 → 发电岗产出 ×调度缺失惩罚（见 §三 3.6，待调）
  - **验收**：构造"电力不足"场景，能看到「研究线先停 → 建造线停 → 调度线最后停」的优先级生效
- [ ] **T2.4 自动化购买与运行**
  - `buyAutomation(line, level, state)`：扣 `数据`（§2.2 表），前置等级齐备（调度→建造→研究 不可跳级）
  - 运行效果（仅「运行」态生效，tick 内驱动）：自动调度补足人力 / 自动建造建最便宜建筑 /
    自动研究研究最便宜科技（Lv2+ 按收益排序）—— **不处理危机**（断电/事故/饥荒仍需人）
  - **验收**：买齐三线 Lv1 后，tick 内能自动补足岗位缺口并建起第一座建筑（控制台验证）
- [ ] **T2.5 核电风险（高风险高回报）**
  - `tickNuclear(state, dt)`：每座核电站 `风险 += 0.0015×dt×(1+废料系数)×(1−维护覆盖率)`；
    `风险≥1.0` 触发事故（轻微/熔毁/灾难三级，§3.3）；核电站每秒产废料 0.002，堆积系数 `min(2, 废料/50)`
  - 维护覆盖率 = `核工程师 / (核电站×8)`，≤1.0；满维护 → 风险累积为 0
  - **验收**：无核工程师时 ≈667s（11 分钟）必出事；满维护时风险恒 0（控制台快进验证）
- [ ] **T2.6 网络与发射（历史演出，非跃迁出口）**
  - `getNetworkBonus(nodes)` = `0.15×√min(nodes,16)`；作用数据产出 ×(1+加成)、算力上限 ×(1+0.5×加成)
  - `tickLaunch(state, dt)`：发射场建成后按 §4.2 里程碑推进，**占用算力 500–1000** 持续数百秒
    （在 T2.1 的"发射占用"中扣除，强制自动化降载）；卫星入轨触发「斯普特尼克时刻」事件（研究 +25%/600s）
  - **验收**：发射进行中，可用算力被扣、自动化面板显示临时降载；不触发任何跃迁
- [ ] **T2.7 终局条件与通关演出（专项任务）** ← 必须包含
  - `checkEndgame(state): EndgameCheck`（§11.8 六项）：① 计算机/半导体/网络核心+支撑全研究
    ② 三线均 Lv3 且自动化运行占比 ≥90% ③ 累计数据 ≥1,000,000 ④ 联网节点 ≥16
    ⑤ 可用算力 ≥1,000 ⑥ 稳定性压力测试通过（连续稳定一段周期，具体口径见 §四待拍板 6）
  - 满足后由 `store.advanceEra` 的同位置改调 `triggerEndgame` → 弹「现代终局」收束文案（§14.3），
    **不调用 `computeEraTransition`（无下一代）**，状态冻结为完成态
  - **验收**：构造满足六项的 E8 终态，`checkEndgame.ok === true` 且收束弹窗可触发；P3 解锁口径见 §四

**T2 验收**：为以上七个子系统各写一段可跑验证脚本（放进 `src/dev/`，跑完即删），证明"新机制正确"且"旧机制未变"。

### 3.3 算力分配与降载级联的精确规则（专门写）

```
// ── 算力总池 ──
C_inst  = Σ(计算中心_i × 单机算力(世代) × (1 + 冷却系数_i + 0.5×联网加成))   // 装机上限
C_raw   = min(C_inst, max(0, E_net) / e)                                  // 电力闸门（min 非平滑）
C_avail = max(0, C_raw − 发射占用 − 程序员占用)                          // 净可用算力

// ── 玩家分配：数据 vs 自动化 ──
C_data  = C_avail × computeDataShare        // 用于产数据
C_auto  = C_avail − C_data                  // 用于跑自动化

// ── 降载级联（runLoadShedding）──
remaining = C_auto
for line in autoPriority:                   // 默认 [调度, 建造, 研究]
    need = c_a(autoLine[line])              // 该线当前等级占用（§2.2：调度 2/6/18…）
    if remaining >= need:
        status[line] = 'run';  remaining -= need
    else:
        status[line] = 'shed'              // 或部分降载（v1 先二态：run/shed）
// 注：未拥有的线（等级 0）不参与分配

// ── 级联放大（调度停摆的正反馈）──
if status.schedule == 'shed':
    schedulingPenalty = 0.7        // TODO(balance)：全局产出 ×0.7，含发电岗
    // → E_net 下降 → 下 tick C_avail 更小 → 更多线 shed（死亡螺旋，§1.4）
```

> **为什么 C_data 与 C_auto 是玩家手里的滑块**：本代核心矛盾是"瓶颈在玩家自己的操作"。
> 把算力在"产数据"和"跑自动化"之间切分，是 E8 第一次要求玩家做宏观取舍（而非堆量）。
> `computeDataShare` 默认值与分段待调（§四待拍板 3）。

### 3.4 半导体与集成电路成本曲线（专门写）

```
// 设计文档 §1.5.1 的"连续指数下降"叙事：
单位算力成本(t) = C₀ × 2^(−(t − t₀) / T)      // T = 18 个月（摩尔式），但仅作"可解释数字"来源

// 落地实现（遵循 §11.2 离散世代 + 效率科技）：
单机算力(世代): 电子管 0 → 存储程序架构 20 → 晶体管 60 → 集成电路 200 → 微处理器 600
单算力功耗 e :                        0.50 → 0.20 → 0.08 → 0.03   // 功耗逐代降（Koomey 定律）
// 摩尔定律（效率科技）：解锁后单机算力随时间渐进 +15%/18 月（非一次性）：
mooreMul(t) = 1.15^(floor((t − t_unlock)/18月))     // 封顶 TODO(balance)，避免无限
有效单机算力 = 基础(世代) × mooreMul × (1 + 磁芯存储 0.10 + 并行计算 0.10 + …)

// 结论：连续曲线不直接给按钮，而是持续压低"同样数据/电力能跑的自动化量"
//       —— 这是 §1 三重链"越成功越脆弱"的反面：成本侧持续松绑
```

> ⚠️ **设计张力**：§1.5 的连续指数曲线 vs §11.2 的 4 档离散世代。本计划落地以**离散世代 + 摩尔定律科技**为准，
> 连续曲线仅用于悬停解释"为什么同样代价能跑更多算力"。两者不矛盾但需明确主从（见 §四矛盾 2）。

### 3.5 `doTick` 的执行顺序（E8 分支，顺序错会算错账）

```
1   电力结算：E_gen − E_pop − E_industry → E_net（断电离网 ×0.5）
2   算力结算：C_inst → C_raw(电力闸门) → 扣发射/程序员占用 → C_avail
3   算力分配：C_data = C_avail×share；C_auto = C_avail − C_data
4   数据产出：(录入员×0.15 + C_data×0.06)×(1+联网加成) → data / dataCumulative
5   降载级联：runLoadShedding(C_auto) → 每条线 run/shed；算自动化管理因子（仅运行级）
6   自动化动作（仅 run 态）：自动调度补人力 / 自动建造 / 自动研究（不处理危机）
7   核电风险：tickNuclear(dt) → 事故分级处理（停机/损毁/K 惩罚/废料）
8   资源产出/消耗：食物/钢铁/铀矿/经验（沿用既有 calc，加 E8 岗位）
9   人口增长：r×P×(1−P/K)×食物因子；r 含 能源因子×自动化管理因子（§11.3）
10  发射推进：tickLaunch(dt)（占用算力已在步骤 2 扣除）
11  终局检查：checkEndgame → 满足则触发现代终局演出（不跃迁）
```

> ⚠️ **为什么电力在最前**：三重链的根是电力；算出 `E_net` 才能定 `C_avail`，进而定数据/自动化/降载。
> 顺序颠倒会导致"缺电但自动化还在跑"的失真（玩家会看到不该出现的平稳）。
> **为什么自动化动作在第 6 步（而非资源前）**：调度补人力影响第 8 步的产出，必须先生效。

## 四、待拍板事项 · 推荐方案

> 每项给推荐与理由。**回"按推荐"或指出要改哪条即可。**

### 4.1 E8 研究货币：经验 vs 研究点 → **推荐：用经验（与设计文档一致）**
- 理由：设计 §11.7 全部 39 项科技成本**明确写"经验"**，§6 资源集也说经验"沿用 E1–E6 通用机制"。
  `数据` 是**自动化货币**（买自动化线），与"研究科技"是两件事，不应混用。
- 代价：与"货币演进 E5→研究点"的规划预期不符（见 §四矛盾 2）。若坚持研究点，需把 E8 全部科技
  `cost` 字段改口径、且 E5 须先实装研究点资源——工作量外溢。本版建议先用经验，研究点留作 E5 自身演进。

### 4.2 半导体成本曲线：连续指数 vs 离散世代 → **推荐：离散世代 + 摩尔定律科技实现**
- 理由：连续曲线 `C₀×2^(−(t−t₀)/T)` 是叙事/可解释数字；落地必须有可交互的"世代跃迁"（晶体管/集成电路/微处理器）
  与可成长的效率科技（摩尔定律 +15%/18月）。主从明确后两者不冲突。
- 代价：连续曲线的"摩尔定律 18 个月"与离散世代的"研发解锁"并存，玩家可能困惑"为什么功耗是跳变的"。
  用悬停解释缓解（§13）。

### 4.3 算力分配滑块（数据 vs 自动化）→ **推荐：引入 `computeDataShare`，默认 0.5**
- 理由：本代核心矛盾"瓶颈在玩家操作"必须有一个玩家手里的旋钮；把算力在产数据/跑自动化间切分
  正是这个旋钮（设计 §1.2 的 C_data / C_auto 就是为此留的）。
- 代价：多一个 UI 控件，增加认知负担。但 E8 的 UI 哲学就是"三个自动化卡片 + 一个分配滑块"（§13），可接受。

### 4.4 降载级联的"级联放大"如何实现 → **推荐：简化模型（调度停摆→全局产出 ×0.7）**
- 理由：完整正反馈环（停调度→发电缺人→电更低→更多停）实现复杂且难配平；v1 用"调度停摆惩罚"近似，
  足以演出"断电保谁"的核心决策，又不至于不可控。
- 待定：惩罚系数 0.7 为 `TODO(balance)`；是否要做完整耦合环留待实测。

### 4.5 联网节点是否硬封顶 16 → **推荐：硬封顶 16**
- 理由：终局条件④要求"联网节点 ≥16"，封顶即"满即停"，避免无限叠（√n 本身边际递减，封顶只是保险）。
- 代价：玩家多建无意义。可接受（终局后本就收束）。

### 4.6 终局条件⑥"稳定性压力测试"口径 → **推荐：连续 300s 未触发降载级联且核电无事故**
- 理由：§11.8 原文"在降载级联/核事故压力测试下连续维持稳定一段周期"。具体时长设计未给，需定一个可测口径。
  推荐 300s（≈5 分钟，呼应核电 11 分钟计时器的一半）无事故 + 无强制降载。
- 待定：时长与"压力"强度（是否需人为制造一次断电再恢复）留 `TODO(balance)`。

### 4.7 P3 星际播种解锁口径 → **推荐：本版不解锁 P3（星海为 E9 扩展位）**
- 理由：P3 原挂"通关星海"，但本版 E8 是终局、星海顺延为 E9（§11.9/§14.2），发射链仅作历史演出。
  若本版解锁 P3 会指向一个不存在的 E9 内容，造成空洞成就。
- 处置：P3 在本版**标记 `locked: 'E9'`**，解锁条件改为"达成现代终局"（收束即点亮，但解锁内容仍是 E9 预留钩子）；
  或在收束弹窗注明"星海/生命/智能留给后来者"。**不要**在 E8 内实装任何星海玩法。
