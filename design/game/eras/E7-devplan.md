### T2 · 引擎层（`src/game/engine.ts` 纯函数优先，建议拆分 `game/grid.ts`）

> ⚠️ **铁律：所有新机制必须时代门控**（`state.era !== 'E7'` 时新分支一律不执行），
> 否则会污染 E1–E6 的既有基线（1163s / 1920s）与 SSR 字节一致性。

- [ ] **T2.1 电网实时平衡**（本代核心机制，建议独立成 `game/grid.ts`）
  - `calcGrid(state)` → `{ supply, load, rho, gridMul, status }`：
    - `supply = Σ(发电厂 × 250) × η_输电`（η 取交流/高压，含电工损耗减免）
    - `load = Σ(耗电建筑×额定) + 住宅×8 + 人口×0.012`（单位必须统一为 kW，见四·待拍板 2）
    - `rho = load > 0 ? supply / load : ∞`（D=0 视为宽裕，避免除零暴死）
    - `gridMul`（节流系数，见三·7.2 精确规则）：ρ≥1→1；0.3≤ρ<1→ρ；ρ<0.3→0.3（蒸汽冗余接管）
    - `status`：宽裕 / 刚好 / 限电降速 / 区域限电 / 电网崩溃
  - `tickRhoSustain(state, dt)`：ρ≥1.05 → `rhoSustainSec += dt`，否则归零（供跃迁条件"持续达标"用）。
  - 区域 ρ：联网前各变电站片区独立算 ρ；联网后全域统一（损耗随距离升）—— 首版可先实现全域版，区域版留 TODO(balance)。
  - **验收**：构造"接满负荷使 ρ<1"的场景，确认耗电建筑产出 ×ρ；ρ<0.3 时产出被钳在 0.3 而非更低。

- [ ] **T2.2 化学合成与污染**
  - `calcFertN(state)`：合成氨产量速率 = `化工工人数 × 2 × gridMul × 催化等级`（见四·待拍板 3 的"工人 vs 建筑"取舍）。
  - `getChemKBonus(state)`：K 化肥增量 = `4000 × 0.4 × ln(1 + N_fert/10)`（与设计 §2.1 / 验算 B 对齐）。
  - `tickPollution(state, dt)`：`Σ(化工厂×0.010 + 炼油厂×0.015) × gridMul × dt − 治理速率`；下限 0。
  - `getHygieneFactor(state)`：`1 − pollution/250`（直接压低 r，沿用 E6 §4.3）。
  - **验收**：建 12 座化工厂时 K 增量 ≈ +1,960；污染升到 100 时卫生因子=0.60。

- [ ] **T2.3 流水线量产 + 需求侧瓶颈**
  - `calcAssemblyRaw(state)`：单线 4 × 规模系数 `1+0.15ln(1+总装配线数)` × gridMul。
  - `getDemand(state)`：`基础 20 + Σ百货×300 + 广告所×(1+0.10×级) + 消费信贷(+25%上限)`。
  - `calcAssemblyEffective(raw)`：`raw × min(1, demand / raw)`（滞销部分不入库）。
  - **验收**：10 条线无需求侧 → 仅 36% 生效；建 3 座百货 → 满效（与验算 C 对齐）。

- [ ] **T2.4 研究货币切换（承接 E5 研究点）**
  - `getResearchCurrency(state)`：E1/E2→`experience`；E3/E4→`knowledge`；E5+（含 E7）→`researchPoints`。
  - `calcResearchOutput(state)`：`人口 × 0.3 × (1+0.03N) × 工程师加成`；**E7 起关闭经验产出通道**（设计口径，字段保留）。
  - **验收**：E1/E2 的 `calcExperienceOutput` 行为逐字节不变。

- [ ] **T2.5 人口模型扩展（K 与 r 双改）**
  - `getCapacity`：追加 `K = 4000(继承 E6) + Σ住宅×200 + getChemKBonus`。
  - `getPopulationGrowth`：r 乘 `getHygieneFactor` 与 `(rho<0.6 ? 0.85 : 1)`（区域限电惩罚）—— 全部 `era==='E7'` 门控。
  - **验收**：E1–E6 的 K 与 r 公式字面上未变（SSR 字节比对 + `autoplay beeline` 1163s 佐证）。

- [ ] **T2.6 跃迁条件扩展**
  - `checkAdvance` 新增：`minRhoSustain`（ρ≥1.05 持续）、`maxPollution`（污染≤70）、`minBuildings`（化工厂≥6 / 装配线≥10 / 炼油厂≥2）、`minPopulation`（≥12,000）、门槛科技「计算机」。
  - **验收**：六项条件在 UI 上逐条显示 ✅/⬜ 与进度。

**T2 验收**：为以上六个子系统各写一段可跑的验证脚本（放进 `src/dev/`，跑完即删），
证明"新机制正确"且"旧机制未变"。

### 7.1 状态层新增字段（电的特殊存储模型）

```ts
// ⚠️ 电【不可囤流量】，不进 getResourceStorage 的容量体系 —— 这是本代机制本质
// 为什么单列：煤/工业品是"存量"（可堆、可封顶），电是"流量"（每 tick 由电网步重算，不累积）
// 所以 GameState 里【没有】 electricity 累加字段；只有派生量供 UI/跃迁读取：
powerSupply: number;   // 发电侧总功率（kW），每 tick 重算
powerLoad: number;     // 用电侧总负荷（kW），每 tick 重算
rho: number;           // 实时平衡率 = supply / load（∞ 表示无负荷）
rhoSustainSec: number; // ρ≥1.05 已持续秒数（跃迁条件"持续达标"用）

// 污染：是【存量】（0–100 累积，承 E6），与电不同，需持久化
pollution: number;     // 0–100，化工厂/炼油厂累积，治理速率抵消

// 研究货币：承接 E5 的「研究点」（跨代并存，按时代取用）
researchPoints: number; // E5+ 的研究货币；E7 科技成本以它结算

// 资源（进 TopBar，按时代显隐；电除外——它是流量不是资源条目）
petroleum: number;   // 石油：石油工产出
fertilizer: number;  // 合成氨/化肥：化工厂产出（→ K 加成）
synthetic: number;   // 合成材料：化工厂副产
industrial: number;  // 工业品：装配线产出（→ 建造/城市化）
steel: number;       // 钢：承 E6（建筑/电网/汽车）
coal: number;        // 煤：承 E6（发电厂燃料，降权）
```

> **为什么电不入库**：设计文档 §1.2 的核心矛盾就是"抽掉囤积缓冲垫"。若把电放进 `getResourceStorage` 的容量体系，
> 玩家就会像囤煤一样囤电，ρ 判定失去意义。因此电在代码里**没有累加字段**，只有 `powerSupply/powerLoad/rho`
> 三个派生量，每 tick 由 `calcGrid` 重算。UI 显示的是"瞬时发电/用电"，不是"库存"。

### 7.2 引擎新增函数（签名与公式）

| 函数 | 公式 / 行为 | 边界情况 |
|---|---|---|
| `calcGrid(state)` | `supply=Σ厂×250×η`；`load=Σ耗电建筑×额定 + 住宅×8 + 人口×0.012`；`rho=load>0? supply/load : ∞` | D=0 视为宽裕（避免除零暴死） |
| `getGridMul(rho)` | ρ≥1→1；0.3≤ρ<1→**ρ**（全城降速，连续平滑惩罚）；ρ<0.3→**0.3**（蒸汽冗余接管基础运转） | 为什么用 ×ρ 而非选择性断电：真实电网无法精细断电，降速让玩家"看见产出缓降"从而去查面板 |
| `tickRhoSustain(state,dt)` | ρ≥1.05 → `rhoSustainSec+=dt`，否则 `=0` | 供 `checkAdvance.minRhoSustain` |
| `getChemKBonus(state)` | `4000 × 0.4 × ln(1 + N_fert/10)` | N_fert 取瞬时合成氨速率（见四·待拍板 3） |
| `getHygieneFactor(state)` | `1 − pollution/250`（下限 0） | 直接乘进人口增长率 r |
| `tickPollution(state,dt)` | `Σ(化工厂×0.010+炼油厂×0.015) × gridMul × dt − 治理`；clamp ≥0 | 为什么 ×gridMul：厂停机则不排污（与"在产出的同时累积"一致） |
| `calcAssemblyRaw(state)` | `4 × (1+0.15ln(1+总装配线数)) × gridMul` | 规模经济 + 电网节流 |
| `getDemand(state)` | `20 + Σ百货×300 + 广告所×(1+0.10×级) + 消费信贷(+25%)` | 需求侧瓶颈的解法集合 |
| `calcAssemblyEffective(raw)` | `raw × min(1, demand/raw)` | 滞销部分不入库——反向瓶颈可视化 |
| `calcResearchOutput(state)` | `人口×0.3×(1+0.03N) × 工程师加成` | E5+ 货币=研究点；E1/E2 仍走经验（门控） |
| `checkAdvance`（改） | 新增 `minRhoSustain` / `maxPollution` / `minBuildings` 类型 | E1–E6 条件结构不动 |

**ρ 判定精确规则（与 §1.1 表一一对应）**：

```
ρ ≥ 1.1      → 宽裕：正常，可继续接负荷
1.0 ≤ ρ<1.1  → 刚好：正常，无冗余；再接负荷即跌破
ρ < 1.0      → 限电降速：所有耗电单元产出 × ρ（全城连锁，连续平滑）
ρ < 0.6      → 区域限电：在 ×ρ 基础上追加 城市不满 +1 级、人口增长率 r × 0.85
ρ < 0.3      → 电网崩溃：产出钳为 ×0.3（蒸汽冗余接管基础运转），全屏告警
```

### 7.3 `doTick` 的执行顺序（重要：电网步必须早于产出步）

```
1  eraElapsedSec += dt
2  【电网平衡步 · 本代新增，必须在此处】calcGrid → supply/load/rho/gridMul；tickRhoSustain
3  资源产出：普通生产者(石油工/电工/司机/工程师) 满速；
            耗电生产者(化工工人/装配工) 产出 × gridMul  ← 节流在此生效
4  资源消耗：人口吃粮；生产投料
5  污染累积：Σ(化工厂×0.010 + 炼油厂×0.015) × gridMul × dt − 治理
6  人口增长：r = BASE × fireFactor × foodFactor × 卫生因子 × (ρ<0.6?0.85:1)
            K = 4000(承E6) + Σ住宅×200 + getChemKBonus   ← 化肥抬 K 在此
            整数增长（沿用现有 populationProgress 机制）
7  量产有效产出：calcAssemblyEffective = raw × min(1, 需求/产出)
8  研究点产出：calcResearchOutput
9  消息与统计
```

> ⚠️ **为什么电网平衡必须放在产出步（第 3 步）之前**：电不能囤，供必须等于求，
> 而 `gridMul=ρ` 是耗电建筑（化工/装配/炼油）产出的**直接乘数**。若不先算 ρ，
> 这些建筑的产出就会用上一 tick 的旧 ρ，导致"限电降速"晚一拍体现——玩家会看到
> 明明 ρ 已跌破 1.0、产出却还满速的诡异现象，破坏本代核心玩法。
> **为什么放在第 1 步之后、第 6 步之前**：G 与 D 都只依赖建筑数与当时人口（state.population 取 tick 初值），
> 与资源产出互不依赖，所以电网步可独立前置；而人口增长（第 6 步）需要的 K（含化肥加成）
> 与 r（含卫生因子、ρ<0.6 惩罚）都依赖第 2/5 步的结果，故排在之后——顺序错会算错账。
> 这与 E3「贸易排在人口之前」同一思路：任何"本 tick 影响人口/产出基数"的系统都要前置。

## 四、待拍板事项 · 推荐方案

> 每项给推荐与理由。**你只需回"按推荐"或指出要改哪条**，不用逐条写方案。

### 8.1 研究货币名「经验」→「研究点」 → **推荐：E7 用 E5 的「研究点」**
- 理由：货币演进已显式化（E1/E2 经验 → E3 知识 → E5 研究点）。设计文档 §11.5/§11.6 的"经验"是**沿用旧称的疏漏**，
  应统一为「研究点」，否则 E7 会凭空退回 E1/E2 的货币，破坏演进链。代价仅是 §11.5 成本表的列名改动。
- 备选：若坚持 E7 重新用"经验"，则必须解释为何 E5 引入的研究点在 E7 被弃用（不建议）。

### 8.2 电的负荷单位统一 → **推荐：全部统一为 kW**
- 理由：设计 §11.2 列建筑负荷为 kW（180/220/260/8/30），但"生活用电"写成"0.012 电/秒/人"；
  验算 A 实际按 `3,600×0.012=43 kW` 使用了它，证明它本就是 0.012 kW/人。把"/秒"去掉、统一标 kW，
  避免实装时单位错配导致 ρ 算错。

### 8.3 化肥产量 N_fert 取「工人」还是「建筑」 → **推荐：取建筑数（与验算 B 对齐）**
- 理由：验算 B 用 `化工厂12座 → N_fert=24`，是按建筑数；但岗位表写"化工工人 2 合成氨/秒"是按工人。
  为配平可解释、且与验算一致，推荐 `N_fert = 2 × 化工厂数 × 催化等级`（隐含 1 工人/厂），
  化工工人的实际产出（研究点/工业品无关）另行单独计。备选：纯按在岗工人数算，但需同步改验算 B。

### 8.4 E6 遗产「蒸汽冗余」如何落地 → **推荐：作为 ρ<0.3 时的兜底系数 0.3，不新增建筑**
- 理由：设计 §1.1 说 ρ<0.3 时"蒸汽冗余接管基础运转"，但 E7 建筑表（8 座）无蒸汽机。
  推荐把"蒸汽冗余"实现为 `gridMul` 在 ρ<0.3 时钳到 0.3（而非无限下滑），不新增建筑、不引入 E6 字段依赖；
  若未来 E6 实装时有独立蒸汽字段，再接其数值。

### 8.5 区域 ρ（变电站分区）首版做不做 → **推荐：首版只做全域 ρ，区域版留 TODO(balance)**
- 理由：全域 ρ 已能承载核心玩法（限电降速/崩溃）；分区独立 ρ 是"网"的空间化，配平面更大。
  首版先交付全域版证明机制，区域版作为后续增量，避免一次做完体量过大（参考 E3 风险 5）。

### 8.6 研究队列（设计 §10）与"队列已移除"的冲突 → **推荐：E7 不 reintroduce 研究队列**
- 理由：代码现实明确"研究队列已被移除（3b958ee）"，且铁律要求不回退基线。设计 §10 的"排入 8 项"属过时描述，
  应删除/改写为"离线研究按 OFFLINE 常量结算，无队列"。E7 只保留离线收益结算，不重建队列系统。
