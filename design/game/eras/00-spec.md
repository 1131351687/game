## 二、全局框架（不可违反）

### 2.1 八个铁律

1. **一时代一核心科技** —— 该时代全部内容围绕核心科技展开，它定义玩家的优化目标
2. **核心科技 = 下一代门槛科技** —— 链式推进：火→农业→文字→法典→印刷术→蒸汽机→计算机→轨道建造
3. **每代必须引入新动词** —— 不能只是数值放大
4. **跃迁是玩家主动决策** —— 不自动触发
5. **旧内容降权而非作废** —— 主引擎期 → 地基期 → 前置期，按时代距离衰减，下限 20% 不归零
6. **从群体出发，不做个体模拟** —— 见 2.3
7. **所有数字可解释** —— 玩家悬停能看到"为什么是这个数"
8. **史实锚点必须标注** —— 每条设计注明依据；有争议的标注"⚠️ 争议"

### 2.2 人口模型（全时代通用）

沿用 E1 的逻辑斯蒂增长，**后续时代不得另起炉灶**：

```
人口增长速率 = r × P × (1 − P / K) × 食物因子

r = 基础增长率 × 环境因子
K = 基础上限 + Σ住所容量
```

- 每个时代改变的是 **K 的来源** 与 **r 的环境因子构成**
- 例如：E2 季节影响 r；E4 版图影响 K；E6 城市化影响 K 与 r

### 2.3 ⛔ 禁止事项（本作定位所决定）

| 禁止 | 原因 |
|---|---|
| 生育间隔、婴儿死亡率、哺乳期、寿命 | **个体层面**，本作是文明游戏 |
| 「技术失传 / 文明倒退」机制 | 已评估不适用 |
| 武器损耗、逐个体装备追踪 | 应抽象为**文明级工具世代** |
| 考古发现 / 考古争议机制 | 时代错乱（考古是现代学科） |
| 强制剧情与对话 | 玩家自己书写文明史 |
| PVP / 排行榜 | 纯单机体验 |
| 必须每天上线的日常任务 | 尊重玩家时间 |

### 2.4 内容规模控制

> **定位**：本作是"**点科技树**"的挂机放置游戏 —— **科技树是主菜**，资源/岗位/建筑是服务于解锁科技的机器。
> 因此科技数量要充足，其他系统要精简。

| 项 | 标准 | E1 实际 |
|---|---|---|
| **科技数** | **E2 30 / E3 45 / E4 60 / E5 75 / E6 90 / E7 100** | **20 项** |
| 新增资源 | 2–4 项 | 5 项（含继承） |
| 新增岗位 | 3–5 个 | 4 个 |
| 新增建筑 | 3–6 座 | 3 座 |

**科技解锁节奏目标**：平均 **4 分钟 1 项**（挂机回来能看到好几个新东西）。

**原则**：科技要**多**，其他系统要**精**。每个非科技项都必须服务于解锁科技的效率。

### 2.5 科技树结构规范（硬性）

每代科技树必须是 **1 主干 + 3 分支 + 汇聚** 结构：

```
                     ┌─────────────────┐
                     │   门槛科技       │ ← 通往下一时代
                     └────────▲────────┘
                              │
      ┌───────────────────────┼───────────────────────┐
      │                       │                       │
 【分支 A 5–8 项】       【分支 B 5–8 项】       【分支 C 5–8 项】
      │                       │                       │
      └───────────────────────┼───────────────────────┘
                              │
                     ┌────────▼────────┐
                     │   核心科技       │ ← 起点，必经
                     └─────────────────┘
```

- **三条分支必须汇聚到门槛科技** → 玩家至少走通一条才能跃迁
- **经验收入必须设计成"无法走通全部三条"** → 形成路线选择

**科技内容配比（硬性规范）**：

| 类型 | 占比要求 | 说明 |
|---|---|---|
| **解锁型**（开新岗位/建筑/机制） | **≥ 40%** | "多出个新东西" |
| **质变型**（改规则，如"采集不再受季节影响"） | **≥ 25%** | "规则变了" |
| **数值型**（纯 +X%） | **≤ 25%** | 超过即为灌水 |

### 2.6 研究队列（必备）

挂机游戏的生命线 —— **没有队列，玩家必须守在电脑前，那就不是挂机游戏**。

每代文档**必须**说明本时代的队列规格：

| 功能 | 要求 |
|---|---|
| 研究队列 | 可预先排入 N 项，自动依次执行（E1 为 5，逐代递增） |
| 离线研究 | 关闭浏览器后按队列推进（上限 8 小时，效率 50%） |
| 队列为空提示 | 必须提示，避免玩家误以为还在挂机 |

## 四、研究方法（重要）

⚠️ **本环境的 `web_fetch` 工具被沙箱拦截**（所有域名返回 "non-public IP address"）。

**可行的取证路径**：

1. 用 `web_search` 定位来源
2. 用 **PowerShell 直连 API** 抓原文核对，例如：
   ```powershell
   Invoke-RestMethod "https://zh.wikipedia.org/api/rest_v1/page/summary/<条目名>"
   Invoke-RestMethod "https://en.wikipedia.org/w/api.php?action=query&prop=extracts&explaintext&format=json&titles=<条目>"
   ```
3. 交叉印证多个来源

**要求**：
- 数字给出**具体年代/数值**，标注是学界常引区间还是推测
- 争议条目明确标注 ⚠️
- 无法核实的，写"⚠️ 待核"，**不要编造**

## 五、质量要求

### 必须做到

- [ ] 核心科技是本章主角，其余内容都服务于它
- [ ] 发展方式与其他时代**明确不同**（不是换皮）
- [ ] 数值有**配平验算**（成本 vs 时长内可获收益）
- [ ] 每个设计决策给出**为什么**，不只是"是什么"
- [ ] 史实锚点具体到年代与遗址/事件名
- [ ] 与前一时代有**继承关系**（旧核心如何降级）

### 禁止

- [ ] ❌ 罗列一堆功能但说不出核心矛盾
- [ ] ❌ 数值凭空写，没有验算
- [ ] ❌ 出现 2.3 节列出的禁止事项
- [ ] ❌ 只写"是什么"不写"为什么"
