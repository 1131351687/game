# E3 城市时代 · 开发任务清单

> **来源**：[`E3-citystate.md`](./E3-citystate.md)（设计规格）＋ [`../era-directions.md`](../era-directions.md)（方案 B 的支点修订）
> **目标**：把 E3 实装为可玩的一代，**并且不破坏 E1/E2 的既有基线**
> **基线**：`demo/` 现有代码 —— 已实装 E1 + E2，E1 门槛 1163s、E2 通关 1920s（8 个冬季），
> `tsc` 0 error，`npm run build` 通过，SSR 逐字节回归可用（见 `03-verification` 守则）
>
> **本代的独特之处**：E3 是目前**最大的一次跨代跳跃** —— 它一次性引入
> ① 记录容量（槽位制硬上限）② 刻录（科技的"二次生命"）③ 贸易路线（虚拟邻邦 + 价格浮动）
> ④ 铜→锡→青铜的生产链 ⑤ 研究货币从「经验」换成「知识」⑥ 规模递减（N^0.9）。
> 前两代的实装经验不能直接套用，必须按下面的顺序推进。

## 二、任务分解

### T1 · 数据层

> 纯数据，零逻辑。数值一律先照 `E3-citystate.md` §11 填入，标 `TODO(balance)` 的部分留待 T6。

- [ ] **T1.1 资源** `src/data/resources.ts`
  - 新增 4 项：铜 🟠 / 锡 ⚪ / 青铜 🥉 / 知识 📜
  - **知识**取代「经验」作为 E3 的研究货币（E1/E2 仍用经验 —— 两者并存，按时代取用）
  - 锡的**本地产出恒为 0**（只能贸易进口）—— 这是本代的设计约束，不是遗漏
  - **验收**：`RESOURCES` 条目数与设计文档一致；`MATERIAL_RESOURCES` 分时代可得

- [ ] **T1.2 岗位** `src/data/jobs.ts`
  - 继承岗位调整：农夫 **3.0 食物/s**、伐木 0.4、打石 0.3、牧民/猎人 1.2（×工具世代）
  - 新增 4 个：铜矿工（0.06 铜，需本地铜矿）/ 冶炼工（0.05 青铜，耗铜 0.045 + 锡 0.005）/
    **书吏（0.15 知识，需空闲泥板槽）** / 商人（1.2 运力/s ÷ 距离系数）
  - 织工去留**待定**（织物目前无消费方）→ 见"待拍板"
  - **验收**：`JOBS` 条目数 = 继承 4 + 新增 4；书吏的 `requires` 能表达"需要至少 1 个空闲槽位"

- [ ] **T1.3 建筑** `src/data/buildings.ts`
  - 民居（220 木 + 120 石 → K +130）｜熔炉（180 石 + 40 铜 → 冶炼 +25%，解锁冶炼工）｜
    **学宫**（260 木 + 200 石 → **记录容量 +5**）｜商栈（150 木 + 60 青铜 → 贸易路线槽 +2）｜
    标准器（100 青铜 → 换算损耗 −5%）
  - **验收**：学宫是**唯一**的记录容量来源；5 座建筑各对应一个限制方向

- [ ] **T1.4 科技集**（新建 `e3-techs-{writing,trade,bronze}.ts`）← **本任务最重**
  - 20 项 = 核心 1（**楔形文字** 800）＋ 支撑 5（泥板制作 1200 / 书吏训练 1800 / 铜锡冶炼 2600 /
    度量衡 4000 / 商队组织 6000）＋ 效率 13（印章封泥 2500 … 档案库扩建 15000）＋ **门槛 1（钢铁 30000）**
  - 每项需标注：`cost(知识)`、`type`、`effects`、`requires`、`recordCost = cost × 10%`
  - **验收**：20 项齐备；门槛科技为「钢铁」（方案 B 后的门槛链：书写 → **钢铁** → 印刷术）

- [ ] **T1.5 常量与元信息**
  - `constants.ts` 新增 `E3` 块：记录容量基础 **3**、每学宫 **+5**、每条路线书吏 **40**、
    贸易价格基准与浮动区间、距离系数 1/2/3、**规模递减指数 0.9**
  - `era.ts`：`ERAS.E3`（核心「书写」、门槛「钢铁」、刻度行）；`ERAS.E2.advanceConditions` 指向 E3
  - **验收**：`ERAS` 出现 E3；E1/E2 的字段一字未改

**T1 验收**：`npx tsc --noEmit` 通过；数据项数与设计文档逐条对上（4 资源 / 4 新岗位 / 5 建筑 / 20 科技）。

### T2 · 引擎层（`src/game/engine.ts`，纯函数优先）

> ⚠️ **铁律：所有新机制必须时代门控**（`state.era !== 'E1'` / `>= 'E3'` 之类），
> 否则会污染 E1/E2 的既有基线（1163s / 1920s）与 SSR 字节一致性。

- [ ] **T2.1 记录容量与刻录**（本代核心机制）
  - `getRecordCapacity(state)` = `3 + 学宫×5 + 泥板制作加成 + 档案库扩建加成`
  - `getUsedSlots(state)` = 已刻录科技数
  - `canRecord(techId, state)` → `{ok, reason}`：① 有空槽 ② 知识 ≥ cost×10% ③ 至少 1 名书吏
  - `recordTech(techId, state)`：扣知识、占槽、把科技从"口头"升为"已刻录"（**不可撤销**）
  - 科技效果口径：**口头 ×50% / 已刻录 ×100%**，并叠加既有的 `eraDecay`
  - **验收**：槽位满时 `canRecord` 返回明确 reason；未刻录科技在 E4 起失效（T3.4 验证）

- [ ] **T2.2 研究货币切换**
  - `getResearchCurrency(state)`：E1/E2 → `experience`；E3+ → `knowledge`
  - `calcKnowledgeOutput(state)`：书吏产出 ×（1 + 书吏训练/六十进制加成）
  - **E3 起关闭「经验」产出通道**（设计明确），但 `experience` 字段保留以免旧存档报错
  - **验收**：E1/E2 的 `calcExperienceOutput` 行为逐字节不变

- [ ] **T2.3 铜 — 锡 — 青铜生产链**
  - `calcResourceOutput` 支持铜/锡/青铜；**锡的本地产出恒为 0**
  - 冶炼工的投入约束：铜/锡不足时**按比例降速**（不是报错，而是"缺料停工"）
  - 再生冶炼（回收率 30%）与熔炉（+25%）进入 `aggregateEffects`
  - **验收**：无锡时冶炼工产出为 0 且 UI 能说明"缺锡"

- [ ] **T2.4 贸易路线**（全新区块，建议先在控制台跑通再上 UI）
  - 数据：4–6 个虚拟邻邦（产出 / 需求 / 距离 1–3）＋ 路线槽位（商栈 +2）
  - `tickTrade(state, dt)`：运力（商人）÷ 距离系数 → 换得货物；价格随买卖浮动（买多则贵）
  - 声望（0–100）修正全部价格；契约可锁价 5 分钟（「契约刻录」延长到 12 分钟）
  - 每条活跃路线需 **40 名书吏**（「账目分类」降到 30）—— 这是"书吏占用"的第二条出口
  - **验收**：能跑出"铜富余但没有锡 → 必须开路线买锡"的完整链路

- [ ] **T2.5 规模递减（N^0.9）**
  - `effectiveOutput = unitOutput × N^0.9`，**仅 E3 及以后生效**
  - **验收**：E1/E2 输出公式字面上未变（可用 SSR 字节比对 + `autoplay beeline` 1163s 佐证）

- [ ] **T2.6 跃迁条件扩展**
  - `checkAdvance` 需支持：`研究「钢铁」+ 已刻录`、人口 ≥1800、青铜 ≥2000、学宫 ≥3、商栈 ≥2、**已刻录 ≥12 项**
  - 复用已有能力：`minBuildings`（多建筑门槛）已就绪，需再加"已刻录计数"类条件
  - **验收**：六项条件在 UI 上逐条显示 ✅/⬜ 与进度

**T2 验收**：为以上六个子系统各写一段可跑的验证脚本（放进 `src/dev/`，跑完即删），
证明"新机制正确"且"旧机制未变"。

### T3 · 系统层

- [ ] **T3.1 存档 v5 → v6**
  - 新字段：`knowledge / copper / tin / bronze / recorded: string[] / tradeRoutes / reputation`
  - 迁移：v5 存档补 0 与空数组即可（**不需要**把经验折算成知识 —— 知识是本代新资源）
  - **验收**：旧档能读、无报错、E1/E2 玩家不丢进度

- [ ] **T3.2 E2 → E3 交接**（`game/transition.ts`）
  - 遵循铁律：**只新增不重置** —— 食物/木/石/牲畜/织物/建筑/岗位/队列原样带过
  - 新增项：本地矿藏（开局或继承时确定）＋ 记录容量基础 3
  - **岗位进阶/退役**：E3 需要决定织工等旧岗位的去留（见"待拍板"）；书吏是本代核心新岗位
  - **验收**：链式跑 E1→E2→E3 后，人口/资源无断崖（`autoplay e3` 首 60 秒人口不崩）

- [ ] **T3.3 离线结算含贸易**
  - 离线按 50% 效率、上限 8 小时；**贸易按离线时长折算**（否则"挂机跑商"会失真）
  - **验收**：模拟离线 1 小时 → 贸易收益与在线 30 分钟的等效量吻合

- [ ] **T3.4 跨代失效验证**
  - 未刻录科技在 E4 起失效；已刻录科技进入档案库并给档案加成（0.03/项）
  - **验收**：构造一个"只刻了 3 项"的 E3 终态 → 在 E4 检查未刻录科技确实不生效

| 3 | **贸易是全新区块**，盲目上 UI 会返工 | 先在控制台跑通 `tickTrade` 与价格浮动，再建面板 |
| 4 | **记录容量是硬上限**，玩家容易卡死却不理解 | 面板必须像 E1 火种一样醒目；`canRecord` 必须给明确 reason |
| 5 | 20 项科技 + 6 个子系统，一次做完体量过大 | 严格按 M1→M4 推进，每个里程碑都可独立验收 |
| 6 | 工作区有**他人未提交的代码改动** | 开工前与用户对齐处置方式，再动 E3 |
| 7 | E3 数值仍是**首轮草案** | 先填值并标 `TODO(balance)`，T6 再校准，不在设计阶段纠结 |

## 六、待拍板（开工前需要用户确认）

1. **织工与织物的去留**：织物至今没有消费方。E3 是把它做成**出口货**（贸易线的一部分）、
   还是像采集者那样**取消该岗位**？（设计文档 §7 的继承岗位里没有织工，倾向取消）
2. **本地矿藏怎么定**：开局随机？还是像 P2「平行文明」那样由玩家选起源？
   （设计文档写"开局或由 E2 选址继承"，需要定下来）
3. **贸易邻邦是固定还是随机**：4–6 个邻邦的产出/距离/需求，每局固定还是每局随机？
4. **是否保留 `经验` 字段**：本计划倾向"保留字段但 E3 起不再产出"，避免旧存档报错。
